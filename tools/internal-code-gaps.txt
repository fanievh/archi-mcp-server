# Internal-code gap registry — the pawl for "no internal project-management codes in source".
#
# WHY THIS FILE EXISTS
#   This repo is curated to a public OSS repo. A reader outside the project cannot resolve an
#   internal tracking code: "B44 center-termination detected" in a log, or "per review M1" in a
#   comment, names something they have no way to look up. The rule (project-context.md, Critical
#   Anti-Patterns) bans such codes from code, comments, log strings and tool descriptions.
#
#   One cleanup pass does not keep a repo clean — the next comment reintroduces the habit. So the
#   rule is enforced by a contract test (InternalCodeContractTest) that scans both source trees,
#   the shipped resource bundle and the published non-source surface, and this file is that
#   test's known-gap list.
#
# THE PAWL (can only tighten, never loosen)
#   Every code family the detector knows about must end up in exactly one state:
#     * CLEAN    -> zero matches in either tree. NOT listed here. This is the target state.
#     * ALLOWED  -> published vocabulary, allow-listed in the test itself, with the test proving
#                   the publication still exists. Only the assessor metric ids qualify.
#     * DEFERRED -> listed HERE, with a measured count that is a LOWER-ONLY ceiling.
#   A family with matches and no entry here FAILS THE BUILD. That is the "a new code family must
#   register or fail" property: reintroducing a banned code costs a deliberate, reviewable line.
#
#   FAMILY_ENTRY_CEILING in InternalCodeContractTest is LOWERED (only ever lowered) in the same
#   commit that removes an entry — the manual, reviewable "click", exactly as tools/size-ratchet.sh
#   does for CEILING_LOC. NEVER raise either ceiling.
#
# DEFERRED IS NOT APPROVED
#   A count here is an admission, not a certificate. It says "the detector sees these and nobody
#   has cleaned them yet" — never "these are fine". Seeding a registry from whatever happens to be
#   in the tree and calling the rule closed is the over-reporting hazard this format exists to
#   avoid, which is why each entry carries the measured number rather than a bare exemption.
#
# WHAT IS NOT DEFERRABLE
#   Four surfaces are gated at zero and have no entries here at all:
#     * any string literal in net.vheerden.archi.mcp/src — these become log output and MCP tool
#       descriptions, so they leave the plugin and reach a user or an LLM agent;
#     * every file under net.vheerden.archi.mcp/resources — the bundle serves these to the agent
#       WHOLE, so there is no literal to extract and every byte counts.
#     * .github/** and tools/** — this repo is curated to a PUBLIC OSS repo, and GitHub renders
#       the CI workflow and the build harness inline. They are the first two files a contributor
#       opens after the README, so a story code there is read by more people than most of the
#       source. docs/** is deliberately NOT scanned: 28 of its 30 matches are Mermaid node ids
#       carrying their own visible human label (subgraph L1["Layer 1: Protocol"]), which is
#       machine syntax a reader resolves on the same line, not an unresolvable code.
#     * the OSGi bundle descriptors — plugin.xml, plugin.properties, build.properties and
#       META-INF/MANIFEST.MF. These are SIBLINGS of src/ and resources/, so they fell between the
#       two scanned roots and were outside every surface this file describes.
#   The second bullet was added after a review pointed out that scanning only *.java left the most
#   directly agent-facing content in the bundle unchecked while this file reported clean. The
#   third was added after a census found 29 codes in ci.yml and 18 in tools/ that no gate saw.
#   The FOURTH was added after an adversarial review asked what sits BETWEEN src/ and resources/,
#   and the answer was six live story codes in files that ship: plugin.properties carried
#   "# Story S6a: human-owned approval-mode toggle" and "# Story S6b: ...", plugin.xml three
#   "Story 1.4" comments. build.properties lists both in bin.includes, and plugin.properties is
#   the externalized-string file whose VALUES become the labels Archi renders in its own menu bar
#   — a shorter path to a user than the resource bundle the second bullet exists for. Three of the
#   six were also invisible in SHAPE: `story-code` was `Story [0-9]+-[0-9]+`, dash-only, and could
#   not match the dotted `Story 1.4`. Both the surface and the separator class were widened.
#
#   A comment, by contrast, is read only by someone already inside the tree. That asymmetry is why
#   every count below is test-tree only: the main plugin is at ZERO for every family here.
#
# LOCALE
#   If you sort this file, pin `LC_ALL=C`. An unpinned `sort` collates differently on macOS (dev)
#   and the C-locale CI runner; that exact false positive already shipped once against the
#   signature baseline (see tools/size-ratchet.sh, "locale pin: REQUIRED, not cosmetic").
#
# FORMAT
#   <family-id> <STATUS> <ceiling> # <reason>
#   STATUS is one of:
#     DEFERRED   — detected and counted; cleanup is scheduled, not done. The ceiling is the
#                  measured match count at the time of the last click and may only go down.
#     COLLISION  — as DEFERRED, but the token also has a legitimate non-code meaning in this tree,
#                  so cleanup must be per-site by hand and can never be mechanical.
#   Blank lines and #-comments are ignored.
