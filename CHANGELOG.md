# Changelog

## v1.8.0 (2026-07-02)

Presentation-fidelity release — making the diagrams the agent produces legible enough to show without hand-fixing. The headline is connection-label legibility: ELK now reserves room for each label's width while it lays a view out, and on **Archi 5.10** the new connection **Label Offset** lets the router lift a Middle label clear of the box it attaches to — with `assess-layout` taught to *see* the label defects (label-on-its-own-endpoint, clipped notes, icon overlaps) that the previous assessor missed, so the agent can detect and fix them in the same loop. This cycle also broadens `assess-layout`'s defect coverage: connections routed *through* a note or image and non-orthogonal *interior* (mid-route) segments now influence the routing rating, redundant collinear bendpoints and same-colour container/child "flat-blob" fills are added as informational signals, and a per-dimension **coverage map** now declares which defect classes a run actually evaluated — so the absence of a finding can be told apart from the absence of a detector. The assessor also closes the label-rendering blind spots the coverage map exposed (a connection **grazing** a note/image border, and a connection **label** dragged onto a note or a group's title band), adds a **de-noised headline** (`overallExcludingAcceptedCosmetics`) that separates accepted ELK terminal-diagonal cosmetics from real defects, and grows a whole-model **`scope: all-views`** sweep for a one-call close-out triage; `export-view` now **stamps each render with the model's mutation version** so a stale image is detectable against a later assessment. It teaches view placement to **auto-recede** an unauthored container fill to a subtle backdrop when a child is nested, so nesting reads as depth rather than a flat block, and lets a view object **anchor** to a container so it follows the target's edge as the target grows or moves — resolved at commit time — instead of freezing at an absolute position that silently drifts. It also teaches the router to **clear an off-face terminal hug** — a connection that leaves an element face then runs a pixel or two parallel, hugging it — in both the full-route pipeline and the `terminals-only` rectifier, with `assess-layout` taught to *see* that same hug (`offFaceParallelTerminalCount`) so detection and fix stay paired. In the same spirit it teaches the router to **dissolve a coincident same-face hub port** — two terminals a downstream stage collapsed onto one perimeter point on a low-degree face — via a gated final spread pass (paired with a new `coincidentFacePortCount` assessor signal that sees the collision M5's four-connection face guard was blind to), and to **surface a layout-bound egress-lift decline honestly** as an `EGRESS_LIFT_LAYOUT_BOUND` warning plus a spread-the-elements next step whenever it rolls back an off-face lift to protect a healthy parallel gap, rather than declining in silence. The M4 edge-coincidence detector now **enumerates every grazed element** instead of stopping at the first; and the coverage map gains two honesty refinements (a contextual `partial` for `labelOverlaps` when a label outgrows its segment, and a standing `not-checked` for the unmeasured `corridorCentering` mode). `bulk-mutate` gains a view-scoped **`set-view-label-expression`** op that stamps one label-expression template onto every eligible object on a view in a single atomic command, collapsing one `update-view-object` call per object into one op per view. It also hardens the request boundary (undeclared and declared non-UTF-8 bodies are now rejected), **rejects a literal HTML/XML entity** in a name or label with a corrective hint instead of silently storing the escaped literal, makes folder-type placement fail fast at mutation time, and fixes two latent layout-fidelity defects (multi-line note auto-fit, compound-undo paint order). A new top-level **`prompts/`** library ships the first ready-to-use agent prompt — `repo-to-archimate-model.md`, also distributed as the `/repo-to-archi` slash command. No tools or resources were added or removed — the surface stays at **69 tools** and **14 resources** (`set-view-label-expression` is a `bulk-mutate` operation, not a new top-level tool). The Archi 5.10 features are runtime-detected and **no-op on Archi 5.7**, so nothing changes for users on the older platform.

### Features

- **Connection labels no longer crowd on dense auto-laid-out views.** When `auto-layout-and-route` runs the ELK layout, it now reserves space for each connection label's estimated text width while it spaces the elements, so labelled edges keep enough room for their labels instead of letting them overlap. The estimate uses the same width yardstick the layout-quality check already measures labels with, so the spacer and the detector agree. Labels you have deliberately hidden (`showLabel` off) — and edges with no label — reserve nothing, so manual label suppression stays an effective way to de-clutter a busy view. Default behaviour for label-free views is unchanged. Verified on a crowded view: connection-label overlaps cleared (2 → 0) after a re-layout, with label-free elements left compact rather than over-spread.

- **Connection Label Offset lifts a Middle label off its own box (Archi 5.10).** Archi 5.10 adds a per-connection "Label Offset" — a Centre-plus-eight-compass anchor that nudges a Middle-positioned label off the connection's midpoint. `auto-route-connections` and `auto-layout-and-route` now use it: when the best along-path label position still leaves a Middle label rendered *on* one of its endpoint boxes, the router scores the eight perpendicular directions and applies the first one that lifts the label clear, choosing the direction from the label's hosting segment so a Z-routed connection gets the right side tried first. The along-path label-position optimizer is itself now **own-endpoint-aware** — it penalises a candidate position that would drape a label over its own source or target box, so it picks a cleaner spot along the route first and the offset stays a fallback for when no along-path position is clean. On `auto-route-connections` the offset is the *only* channel that can clear this bleed, because a hand-tuned view keeps its positions; on `auto-layout-and-route` it is a last-resort fallback after element re-spreading. The offset is metric-neutral (it moves the rendered label without changing the route geometry the assessor scores). **Runtime-guarded:** on Archi 5.7, with no Label Offset feature, the step is a silent no-op. One caveat to verify in the editor, not an export: Archi's PNG/SVG export renderer does not draw the offset — only the live editor and the Properties panel show the lift (use `get-view-contents`, below, for a programmatic read-back).

- **`get-view-contents` reads back a connection's Label Offset.** `ViewConnectionDto` gains a nullable `relativePosition` field (the Archi 5.10 "textRelativePosition" anchor), so an agent can confirm an offset actually landed — the programmatic channel that neither `assess-layout` nor `export-view` exposes. The field is omitted (`NON_NULL`) when the platform lacks the feature or the anchor is the un-offset default (Centre), so the wire format is byte-identical on Archi 5.7 and for any connection without an explicit offset.

- **Pending Approvals cards gain a `Copy JSON` button.** Each proposal card in the **Pending Approvals** dock now carries a secondary, left-aligned **`Copy JSON`** button that copies the proposal's full structured payload to the clipboard — `proposalId`, `tool`, `status`, the server-generated `description`/`effectDescription`, `currentState`, `proposedChanges`, `validationSummary`, `createdAt`, and the optional agent `intent` — for pasting into an issue or log, or inspecting the complete change before deciding. It is read-only and side-effect-free: the proposal stays pending, the model is untouched, and the internal session-routing key is never included.

- **Nesting a child auto-recedes an unauthored container fill to a backdrop.** When `add-to-view` or `add-group-to-view` places a child *inside* a container element or group whose fill colour you have not explicitly set, the parent's fill now automatically recedes to a subtle light backdrop (`#F4F4F4`) so the nested content reads as foreground-on-depth instead of a flat single-colour block — the standard "the container is the canvas, the children are the figures" convention, applied without the agent having to colour it by hand. The recession is **provenance-gated and idempotent**: only a container with no author-set fill is touched, an already-receded parent is left alone, and an explicitly coloured container is sacrosanct. The root view is excluded structurally, and the recede rides the placement as one atomic undo unit. Opt out per call with `recede: false`. A new informational `assess-layout` signal (`containerFillEqualsChildCount`, below) backstops the case where a container's *authored* fill still equals a child's. Default behaviour for elements placed at the top level (no container parent) is unchanged.

- **A view object can anchor to a container and follow it as it grows or moves.** `update-view-object` gains optional **anchoring**: a note or child records an anchor `{anchorTarget, anchorEdge, dx, dy}` so its position is resolved from the target container's *current* bounds at commit time instead of a frozen absolute snapshot. Edge `below` (default) tracks the target's growing bottom; `above` / `right` / `left` track the corresponding edge. When a later mutation moves or grows the target, every object anchored to it is repositioned **within the same undo unit** — so the flagship note-below-a-group stays aligned as the group grows, instead of silently drifting the way a captured absolute position would. Target and object must share a coordinate space (same parent); self-anchors and cross-space anchors are rejected on set and skipped in the cascade. `add-note-to-view`'s content-relative placement now delegates to the same edge resolver (byte-identical rounding), and the resolved anchor reads back on the `update-view-object` result. Existing calls that pass no anchor are unchanged.

- **`export-view` stamps each render with the model's mutation version, so a stale image is detectable.** Every `export-view` response now carries the model's monotonic mutation counter as `modelVersion` (inline mode: a top-level field; file mode: in `_meta`), the same counter `assess-layout` and the other tools already report. It is a decimal-encoded integer — **compare it numerically, not as a string**. Against a later `assess-layout` `_meta.modelVersion`: if the export's `modelVersion` is numerically lower, the model changed after the render and the exported image is stale — re-export before relying on it for a visual close-out. Previously the inline formats stamped no version and the file mode stamped `null`; the route geometry and image bytes are unchanged. This closes the verification gap where an agent could assess a freshly-mutated model against a render taken before the mutation.

- **`bulk-mutate` gains a view-scoped `set-view-label-expression` op for stamping one label template across a whole view.** A new `set-view-label-expression` operation applies a single `labelExpression` template — e.g. `${name} ${property:evidenceMark}` — to every eligible diagram object on one view in a single atomic command, collapsing what used to be one `update-view-object` call per object into one operation per view (the common case when an agent retro-fits an evidence-mark or status glyph onto an existing diagram). It is **retroactive, type-filterable, and idempotent**: the default scope is ArchiMate **element** objects, and an optional `objectTypes` array widens it to notes and groups; a non-blank-name guard skips any object whose name is blank when *setting* a template (so a placed object never renders a half-empty glyph), but is bypassed when *clearing* (an empty/blank expression removes the override everywhere). The whole sweep is one GEF command, so it is a single undo unit, and the per-op result reports `appliedCount` / `skippedCount`. It is a `bulk-mutate` operation, not a new top-level tool — the served `bulk-mutate` description advertises it automatically. Verified live on a real view (11 applied / 1 skipped, the glyph renders, a note shows no ghost token, and undo restores the model byte-for-byte).

- **The router now clears an off-face terminal hug — a connection that leaves a face then runs parallel hugging it.** When a terminal route departs an element face and then runs a pixel or two *parallel* to that same face before turning, the result reads as a connection grazing the box it attaches to. `auto-route-connections` (and `auto-layout-and-route`) now push that first trunk clear of the face, in **both** routing modes. In the full-route pipeline, the terminal egress-clearance pass replaces an over-strict, wrong-axis "never reduce the vertical parallel-gap" guard with a **dual-axis healthy-floor** model: it enforces a healthy minimum parallel gap (`HEALTHY_PARALLEL_GAP_PX`, 15 px) on *both* the vertical and horizontal axes, so a healthy-to-healthy tightening is allowed while a push into the danger zone stays blocked — and a short-run sub-10 px micro-hug of an element's *own* face (which the foreign-edge overlap test was too coarse to see) is now caught by an own-face short-circuit plus an off-face-stub keep-signal that mirrors the assessor's 8 px oracle. In `mode: "terminals-only"` — which renders centre → L-bend → trunk, so the hug is the trunk *after* the L-bend and the full pipeline's pass cannot be reused — the same healthy-floor is mirrored as pure geometry in the routing pipeline, with a per-side orthogonality backstop that declines any lift which would introduce a diagonal. Detection fires at the 8 px oracle threshold (so an already-clearing terminal is byte-identical) and pushes to 15 px. The work is metric-neutral where nothing hugs, and it drives the new `offFaceParallelTerminalCount` signal (below) to zero. Verified live on a dense view: off-face parallel-terminal hugs cleared (3 → 0), the live geometry matching the headless route byte-for-byte.

- **The router dissolves a coincident same-face hub port.** A downstream terminal stage can pull one connection's source-exit and another's target-entry on the *same low-degree element face* onto that face's centre, collapsing two terminals onto one perimeter port — two edges that appear to leave a single point (the `coincidentFacePortCount` defect the assessor now sees). `auto-route-connections` (and `auto-layout-and-route`) add a gated **final spread pass** in the full-route pipeline that groups terminals per face, clusters them by along-face slot, and for each collision moves whichever terminal *can* move to a free on-line slot (swapping the anchor when the one tried is an immovable face-hug), avoiding every other terminal already on that face. Every move is gated — element degree below the hub threshold (a dense hub keeps its own distribution), the terminal on the perimeter, a provable collision, a free slot at least the 12 px distinguishability floor from every occupied one (else the collision is accepted rather than forced), the relocated stub staying perpendicular, and zero new edge or obstacle crossing — so the pass is a **byte-identical no-op except on an actual collision** and needs no routing-corpus re-baseline. Verified on the organic hub view: coincident ports fan apart with no crossing rise.

- **`auto-route-connections` surfaces a layout-bound egress-lift decline honestly instead of silently.** When the router generates an off-face terminal egress lift but then rolls it back — because applying it would narrow a parallel-connection gap below the 15 px healthy floor — the residual hug is *layout-bound*, not a routing bug the tool can fix on its own. The response now reports the rolled-back count as an `EGRESS_LIFT_LAYOUT_BOUND` structured warning (alongside the free-text warning) plus a matching layout-bound `nextSteps` entry that names spreading the elements sharing the departed face, rather than declining without explanation. It is **signal only** — the routing decision, the routed geometry, and the assessed rating are all unchanged. `assess-layout`'s off-face remedy (above) cross-references the same warning so detection and remediation advice stay consistent.

### Prompts

- **New top-level `prompts/` library — ready-to-use agent prompts.** A `prompts/` folder is now the canonical home for self-contained prompts that drive the server with an LLM agent: paste one into a session that has the Archi MCP tools connected, fill any `{{PLACEHOLDER}}` tokens, and run. It ships with one prompt:
  - **`repo-to-archimate-model.md`** — reverse-engineer a code repository into a full, evidence-marked **ArchiMate 3.2** model: elements, relationships, folders, views, and connections across as many layers as the code and its docs support, building a Context → Landscape → Component stack of views with every concept marked by evidence strength (documented / code-derived / inferred). The run is iterative and resumable — the open Archi model is the durable checkpoint, so an interrupted run can be continued by re-running. It can target a specific tag, release, branch, or commit.
- **`/repo-to-archi` Claude Code slash command.** The same prompt is distributed as a slash command that embeds a copy of the prompt plus a repository-argument token and a clone step. The command copies do not auto-update — the `prompts/` folder is the source of truth, and editing a prompt there means re-syncing its command copies.
- **`repo-to-archimate-model.md` gains an annotation close-out gate and a hard requirements-vs-guidance split.** The prompt now opens with a manifest separating the run's hard requirements (must hold before the model is called done) from its soft guidance (recommended but not blocking), so an agent never silently downgrades a requirement to advice. A terminal close-out gate requires, per touched view, an `assess-layout` pass *and* an eyeballed `export-view` (notes and images included) before the run is complete, and the re-query step that resolves ids is widened to cover unnamed objects. The build sequence also gains two ordering invariants that keep late geometry moves from silently invalidating earlier work: an **annotate-LAST** step (no geometry-mutating call after a note/legend/image is placed, since a placement below content is silently invalidated if the container later grows) and, immediately before it, a **collapse-redundant-bendpoints** step (a targeted `auto-route-connections mode=terminals-only` on any connection with `connectionRedundantBendpointCount > 0`, then re-assess to confirm zero) that clears the collinear terminal micro-jog which pins Middle-positioned branch labels against tiny junctions. Companion guidance sharpens documentation depth (a durable-vs-volatile rule with a 3–5 line budget) and view completeness (a subsystem with three or more collaborators earns its own view; a prose-only subsystem is a missing view). It also grades a folded/grouped box (one element standing for two or more classes, or a `…Family`/`…Handlers`/`…group` name) as `inferred-structural` **at create time** rather than catching the over-claim only at close-out, prefers `column`/`row` over `grid` arrangement when a group's child sizes are uneven, and flattens a subsystem whose members each wire to *external* elements (nesting only when the wiring stays internal). Prompt-only; the source `prompts/repo-to-archimate-model.md` and both `/repo-to-archi` command copies are kept byte-identical in body.

### Layout Quality Assessment

`assess-layout` learns to see several label/visual defects it was previously blind to, so the agent can catch them programmatically instead of only on a human's screen — plus a new hub-to-neighbour crowding signal, two routing-rating-affecting route-quality detections, and a coverage map that makes "we checked it and it's clean" distinguishable from "we never looked". Except where noted, these do not change the overall rating.

- **A connection label rendered on its own endpoint box is now flagged.** The label-overlap detector previously excluded a connection's own source and target from the overlap test (so a label always "grazing" the box it attaches to would not false-positive), which left a real defect invisible: a Middle label that bleeds substantially onto its endpoint. It is now flagged when more than 30% of the label's render-calibrated area falls on its own endpoint — asymmetric by design, so light grazing is tolerated while a clear bleed is reported, naming the more-overlapped endpoint. This is the detection half of the Label Offset fix above. Three companion rules close the cases the area-fraction alone missed: a **box-coverage** test flags a label that blankets a *tiny* endpoint box (e.g. a 14×14 junction sitting almost entirely under a label registers low label-area overlap but ≥ 60% box coverage); a **short-segment** promotion lowers the bar to 15% when the label is wider than the first/last segment it anchors to — the long-source/target-label-on-a-short-segment bleed the assessor used to under-count; and a **junction** rule drops the own-endpoint bar to a near-zero 5% when the endpoint is a Junction, because a junction renders as a solid dark shape with no readable interior — so the box-grazing tolerance a normal box earns is wrong for it, catching an *oversized* junction (e.g. the 120×55 default) grazed by a label that the box-coverage rule, which only fires on a tiny junction, would miss. The detector is also now **offset-aware**: a Middle label that has already been lifted clear by an Archi 5.10 Label Offset is not re-reported as bleeding.
- **Label width is render-calibrated.** Connection-label overlap detection now widens the estimated glyph box by the same 1.35× render-versus-measure factor already used for element-label truncation, because Archi renders glyphs wider than the raw estimate and short, tight segments were under-flagged. This is detection-only — the routing-side label-width *reserver* deliberately keeps the raw estimate, so the detector is intentionally the more render-accurate of the two. Suppressed labels (`showLabel` off) correctly reserve and flag nothing, so manual label suppression is no longer penalised with phantom overlaps.
- **Clipped notes are detected (informational).** A new `noteClipCount` / `noteClipDescriptions` signal flags a note whose text needs more height than its box provides — typically an explicit `height` that defeats the server's auto-fit. It uses the same SWT text measurement as the note auto-fit path, so it fires exactly on the auto-fit-defeating case. Remedy: omit the note `height` to let the server fit it, raise the height, or reduce the font size. No rating impact.
- **Image-overlap detection is made accurate (informational).** The image-sibling-overlap detector now also examines **specialization / profile icons** (resolved from the element's profile when the view object carries no custom image), not just custom images, and sizes the image rectangle from the archive's **true pixel dimensions** instead of a fixed 24 px assumption — so it stops both missing real icon overlaps and mis-measuring large images. No rating impact.
- **Hub-to-neighbour crowding is now measured, and a crowded resize can no longer rate `good` (rating-affecting).** A new `hubNeighbourClearanceMin` field reports, in pixels, the smallest clearance between a hub element's edge and the row of spoke neighbours packed against it — measured only on a face carrying at least three overlapping spoke neighbours, so an ordinary element never registers. It exists because the previous metrics had no way to see the failure mode where enlarging a hub to fix port distribution crowds its neighbours: a layout could read `good` on every existing metric while rendering tighter than an alternative that scores only `fair`. A clearance below the 60 px crowding floor now caps the layout tier so a crowded hub cannot rate `good`; a clearance at or above the floor — and the `-1.0` "no measurable hub" sentinel — leave the rating untouched, so no previously-clean view changes tier. The field is appended to the result (older clients ignore it).
- **`assess-layout` next-steps diagnose a saturated container-nested hub.** When corridors are near-saturated (`corridorUtilisationScore ≥ 0.9`) with edge-coincidence pressure and hub-port quality is *not* the limiter, `nextSteps` now emits a single diagnostic step that supersedes the generic spacing-inflation advice — because spacing inflation is the wrong lever there. The step points at `detect-hub-elements` and branches on the new clearance reading: a sparse hub (clearance ≥ 60 px) gets the *enlarge-then-re-route* lever; a dense hub (clearance below the floor) gets the *revert-to-normal-size, re-place with ELK, then full re-route* lever; and the un-measurable case presents both, deferring the choice to `detect-hub-elements` and a render check. Every branch carries the render-authoritative caveat — the rating alone can score a crowded layout `good`, so confirm with `export-view`.
- **The off-face terminal-hug next-step is now router-consistent and honest.** When `assess-layout` reports an `offFaceParallelTerminalCount` hug, its remedy branch no longer over-promises a perpendicular re-route it cannot guarantee. It gives a confident *layout* fix only when the local corridor is below the healthy floor; otherwise it defers to `auto-route-connections` (cross-referencing the router's new `EGRESS_LIFT_LAYOUT_BOUND` warning, below), because the router may legitimately decline the lift to protect a parallel-connection gap; and on a *contested* hub face (two or more connections sharing it) it names **spreading the connections** rather than a plain widen. Signal/description only — no rating changes.
- **Connections routed through a note or image are flagged, and any crossing nudges the routing rating to `good` (rating-affecting).** A new `connectionThroughNoteCount` / `connectionThroughNoteDescriptions` signal flags a connection whose route runs straight through a Note's box or through an element's rendered image rectangle (the "the line crosses the caption/legend" defect). Notes are deliberately excluded from the element pass-through scoring set, and for an image-bearing element this tests the rendered image *rectangle* — which can overhang the element box — so it catches clutter the box-based `connectionPassThroughs` (Tier-1R) misses. It is a Tier-3R routing detection with **binary presence** semantics: a single crossing caps the routing tier at `good`, and several crossings rate the same (one line through a note is already jarring; more is not "worse" for tiering). Where a route trips both this and the box-based pass-through, the routing tier takes the worse of the two, so the Tier-1R pass-through dominates and there is no double penalty. A visual on a connection's own endpoint or container is not flagged. Counted per connection × visual. Reroute the connection or move the note/image clear.
- **Non-orthogonal interior (mid-route) segments are flagged and rated (rating-affecting).** A new `nonOrthogonalInteriorSegmentCount` / `nonOrthogonalInteriorSegmentDescriptions` signal generalises `nonOrthogonalTerminalCount` from the source/target segments to the *interior* of a route: any segment more than ~5° off horizontal/vertical that sits between the two terminal segments. It is a Tier-2R routing detection, ratio-bucketed identically to its terminal sibling (a low interior-diagonal-per-connection ratio rates `good`, a high one `fair`); the two are separate breakdown entries, but the routing tier combines them by the worse, so a connection diagonal at both a terminal and an interior segment is capped once. Counted per connection. Re-run `auto-route-connections` for clean orthogonal paths.
- **Redundant (collinear, removable) bendpoints are detected (informational).** A new `connectionRedundantBendpointCount` / `connectionRedundantBendpointDescriptions` signal flags a bendpoint that lies on — and between — its two neighbours along a *horizontal or vertical* run, so removing it would not change the rendered orthogonal route (the "many unnecessary bendpoints / wobbles" defect). The test is deliberately **axis-aligned** (a triple's `min(spanX, spanY)` within a 0.5 px reconstruction-noise epsilon), not any-angle, so it matches the router's exact `removeCollinearPoints` contract — the agent's only remediation lever: a near-collinear *diagonal* micro-jog is not flagged, because removing it would diagonalise an orthogonal segment. Router-pinned **terminal egress-stub ports** (a first/last bendpoint on its element's perimeter face, held for terminal anchoring / port distribution) are also excluded, because a full re-route never removes them — so a nonzero count is a genuinely collapsible *interior* point. It is counted per redundant point and is distinct from the reversal-based `zigzagCount`. No rating impact. Straighten the route or re-run `auto-route-connections` — `mode: "terminals-only"` now also sweeps these interior collinear survivors (an inserted terminal L-bend that lands collinear with the trunk) while leaving the pinned terminal anchors untouched, so a terminals-only re-route drives the count toward zero.
- **Same-colour container/child "flat-blob" fills are detected (informational).** A new `containerFillEqualsChildCount` / `containerFillEqualsChildDescriptions` signal flags a container whose *authored* fill colour equals a nested child's fill, so the parent and its children merge into one flat single-colour block. It is the backstop for the new auto-recede behaviour (above): because nesting a child now auto-recedes an *unauthored* container fill, this only fires on a blob produced by an *explicit* same-colour fill. Counted per container. No rating impact. Give the container a distinct (lighter) fill.
- **A per-dimension coverage map distinguishes "checked and clean" from "partially checked" from "never evaluated" (informational).** `assess-layout` now returns a `coverage` map keyed by defect dimension, each value one of `checked` (the detector ran and fully covers this dimension's failure modes — so a zero/absent metric means genuinely clean), `partial` (a detector ran but covers only *some* of the dimension's failure modes — a zero/absent metric means only the covered modes are clean, so the uncovered modes must be render-verified before certifying clean), `not-checked` (no detector evaluated this class — absence of a finding is *not* evidence of absence), or `not-applicable` (the view structurally cannot exhibit it). The map is always present on a normal assessment (empty only on degenerate empty/single-element views), is informational and never affects a rating, and lets a done-gate read both `coverage` and `ratingBreakdown` so a dimension counts as "clean" only when `coverage == checked` *and* the breakdown passes. The `partial` level was introduced for two dimensions — `connectionThroughNote` and `labelOverlaps` — whose detectors were known to miss adjacent failure modes. The new graze, label-on-note, and label-on-group detections below close the `connectionThroughNote` gap, so it reports `checked` again. `labelOverlaps`, however, now carries a **contextual** `partial`: the registry still *declares* it `checked`, but on any run where a label is wider than its hosting segment (`shortSegmentCount > 0`) the map downgrades it to `partial`, because a label can crowd a neighbour box while still clearing it geometrically — so the overlap count is honestly zero yet the crowding mode is unverified. A clean run (no over-wide labels) keeps the whole map `checked`. Separately, a new `corridorCentering` dimension ships as a standing **`not-checked`**: it makes explicit that `corridorUtilisationScore` measures multi-occupant corridor *spread*, not whether a single route centres in its corridor versus hugs an edge — a mode no detector evaluates (`corridorUtilisation` itself stays `checked`, fully covering its own scoped question). The `partial` and `not-checked` levels remain defined for dimensions added later.
- **A de-noised headline rating separates accepted ELK cosmetics from real defects.** `ratingBreakdown` now carries `overallExcludingAcceptedCosmetics` — the same overall rating recomputed with the `nonOrthogonalTerminals` contribution removed. Diagonal terminal segments are the straight-line signature of ELK auto-layout and routinely push an otherwise-clean view to `fair`; comparing the two readings tells a real defect from an accepted cosmetic. When `overallRating` is `fair` but `overallExcludingAcceptedCosmetics` is `good`/`excellent`, the `fair` is terminal cosmetics only (run `auto-route-connections` mode `terminals-only` to clear it, or accept it); when the two are **equal**, the rating reflects a real routing/layout defect to fix. It is a **floor, never a lift** — it can only equal or improve `overallRating`, never worsen it — so no existing rating moves down. The headline `overall` value is byte-identical to before (the de-noised value is computed on a copy).
- **`assess-layout` gains a whole-model `scope` for a one-call close-out sweep.** A new `scope` parameter takes `single` (default — unchanged behaviour, full assessment of the one `viewId`) or `all-views`, which assesses every diagram in the model and returns a compact map keyed by view id: each value carries `{name, overallRating, overallExcludingAcceptedCosmetics, elementCount, connectionCount, overlapCount, nonOrthogonalTerminalCount, connectionPassThroughCount}`. It omits violator ids, descriptions, and the per-metric breakdown — one cheap overview instead of one full payload per view — so a final close-out can triage the whole model at a glance, then drill into any `fair`/`poor` view with a single-scope call. `viewId` is ignored under `all-views`; an empty model returns an empty map.
- **A connection grazing (clipping) a note's or image's border is flagged (informational).** A new `connectionGrazesVisualCount` / `connectionGrazesVisualDescriptions` signal flags a connection whose route touches or clips the *border band* of a Note or image — the outer strip that the through-visual interior test (`connectionThroughNoteCount`, above) discards — including a visual too small to inset that a route crosses at all. It is **disjoint by construction** from the interior through-visual count: a single crossing is classified as exactly one of *through* or *graze*, never both, so the two never double-count the same line. Counted per connection × visual. No rating impact. This is the detector that flips the `connectionThroughNote` coverage dimension from `partial` back to `checked`. Reroute the connection or move the note/image clear.
- **A connection label rendered on a note is flagged (informational).** A new `labelOnNoteCount` / `labelOnNoteDescriptions` signal flags a connection *label* (not the route) rendered on a Note's rectangle — the caption/legend collision the route detectors cannot see, because a label is positioned independently of the line it annotates. Counted per label × note, independent of the through-note and graze route signals. No rating impact, and a new `labelOnNote` coverage dimension reports `checked`. Reposition the label (apply a Label Offset or re-run `auto-route-connections`) or move the note clear.
- **A connection label rendered on a group's title band is flagged (informational).** A new `labelOnGroupCount` / `labelOnGroupDescriptions` signal flags a connection label rendered on a visual Group's **title band** — the top title strip — which the connection-label-overlap detector cannot see because it skips groups wholesale as transparent containers. Only the title strip is tested, so a label sitting inside the group *body* is normal and not flagged. Counted per label × group. No rating impact, and a new `labelOnGroup` coverage dimension reports `checked`. Reposition the label or reroute the connection clear of the group title.
- **An off-face parallel-terminal hug is flagged (informational), as the detector half of the router's egress-clearance fix.** A new `offFaceParallelTerminalCount` / `offFaceParallelTerminalDescriptions` signal flags a connection whose terminal route *departs* an element face and then runs **parallel to and hugging** that same face — the first exterior segment travels along the departed face within `OFF_FACE_MIN_STUB_PX` (8 px) of it. This closes a blind spot in the angular terminal check (`nonOrthogonalTerminalCount`): when a route exits a fraction of a pixel off the perimeter and turns to run just beside the face, the exit stub is a sub-perceptible diagonal that the visible-length guard suppresses — so the terminal detector sees nothing, yet the parallel hugging trunk is plainly visible. The departed face is resolved through the same terminal-slot helper the assessor already uses (which attributes a face even for a bendpoint a pixel off the perimeter), not the raw segment angle. Counted per connection, with its own `checked` coverage dimension. **Measurement-only** — the rating-bearing `nonOrthogonalTerminalCount` and its visible-length calibration are untouched, so no rating moves. It is the oracle the new router egress-clearance work (above) drives to zero.
- **A coincident same-face port is flagged (informational).** A new `coincidentFacePortCount` / `coincidentFacePortDescriptions` signal flags an element face on which two or more connection terminals collide onto the *same* perimeter port (within ~1 px along the face axis), so two edges appear to leave one point. This closes a blind spot in the M5 hub-port-quality metric (`hubPortQualityScore`): its per-face guard only scores a face carrying four or more connections, so a face with two or three coincident terminals reads a vacuous `1.0` despite the collision. The detector clusters ports with the same greedy slot sweep the distinct-slot count uses and flags only a cluster holding two or more *distinct* connections, so it neither over-attributes a chain of near-tolerance ports nor mistakes a self-referencing connection for a collision. **Measurement-only** — the count never enters the rating, so M5 and every existing rating are untouched. It is the oracle the new router coincident-port dissolution (below) drives to zero, with its own `coincidentFacePorts` violator key and `checked` coverage dimension.
- **The edge-coincidence detector now enumerates every grazed element (informational).** The M4 edge-coincidence detector previously stopped at the *first* grazed element per connection, so a connection whose trunk hugs the edges of three elements reported only one — and surfaced a single, arbitrary violator. It now enumerates every distinct `(connection, element)` graze: a new informational `edgeCoincidenceGrazedElementCount` (the sum of distinct grazed elements across all connections) and a new `edgeCoincidenceGrazedElements` violator key carrying the grazed *element* ids. The rating-bearing `connectionEdgeCoincidenceCount` and its existing `edgeCoincidence` (connection-id) violator key are **byte-identical** — the per-connection count and violator are now guarded behind a once-per-connection flag — so the rating and the legacy report are unchanged; only the new informational count and element-id key are added.

### Security & Hardening

- **Undeclared and declared non-UTF-8 request bodies are now rejected (HTTP 415).** Two new Jetty handlers, both default-on, close the request-encoding gap. A header-only check rejects any request whose `Content-Type` declares a non-UTF-8 `charset` (e.g. `charset=iso-8859-1`) without reading the body; a second, body-scanning check reads a POST body once (still bounded by the 32 MiB size cap) and rejects it if the bytes are not well-formed UTF-8 — catching a client that sends Windows-1252 / ISO-8859-1 bytes with *no* declared charset, which the header check cannot see. Both render the canonical JSON-RPC error envelope (`-32600`, `httpStatus: 415`). A body that legitimately contains a genuine `U+FFFD` is accepted (the scan tests well-formedness, not a replacement-character literal), and a conformant client — no charset, or `charset=utf-8` — passes through byte-for-byte unchanged. The checks sit innermost in the guard chain (after the size, Origin/Host, and bearer-token gates), each with its own kill switch (`-Darchi.mcp.rejectNonUtf8=false`, `-Darchi.mcp.scanBodyUtf8=false`).
- **Literal HTML/XML entities in a name or label are rejected, not silently stored.** A mutation whose supplied name, label, view-object text, or `labelExpression` contains a well-formed HTML/XML entity token (`&amp;`, `&lt;`, `&#160;`, `&amp;amp;`, …) is now **rejected with a corrective hint** instead of storing the escaped literal — closing the recurring `&amp;` footgun where a value pasted from JSON-escaping muscle memory would render the five-character literal where a human expects a single `&`. The grammar (`&(amp|lt|gt|quot|apos|#[0-9]+|#[xX][0-9a-fA-F]+);`) requires the trailing `;`, so a bare ampersand and non-entity text (`R&D`, `A & B`, `<tag>`, `${name} & ${property:x}`) pass through and are stored byte-for-byte. The rule covers element / relationship / folder / view / specialization / clone names, group and note labels, view-object text, and the `update-view-object` / `set-view-label-expression` `labelExpression`, across `create-*` / `update-*` / `add-*` and their `bulk-mutate` equivalents. Auto-unescaping was rejected as lossy and ambiguous (a genuinely-intended `&amp;amp;amp;` would be corrupted), keeping the plugin a faithful verbatim store.
- **Folder-type placement now fails fast at mutation time.** Placing a concept into a folder whose ArchiMate layer is illegal for it (e.g. a Junction under the Application folder) was previously accepted at the API and only refused later by host Archi when it tried to save the model ("Object is in wrong folder type"). `create-element` and `move-to-folder` now reject it immediately with `FOLDER_LAYER_MISMATCH`. The check delegates to Archi's own `getDefaultFolderForObject` rather than a hand-maintained type→folder map, which closes a real gap — the old map returned no answer for Junction, Grouping, and Location, so those silently skipped validation — and covers relationships for free. `move-to-folder` was previously unguarded entirely; it now enforces the same rule as `create-element`.
- **Duplicate tool-name registration fails fast (developer-facing).** The internal tool registry now rejects a second registration of an already-registered tool name with an `IllegalStateException` at the source, instead of silently accumulating a duplicate that a discovery test caught only after the fact. This affects extension authors registering custom handlers; the normal boot path (each tool registered once) and the clear-then-re-register restart lifecycle are unchanged.

### Fixes

- **Multi-line note and group-label auto-fit no longer grows quadratically.** When a note or group label's `height` is omitted, the server auto-fits the box to the wrapped text. For multi-line content the height grew roughly with the *square* of the line count and clamped at the 600 px maximum, because a single line's height was derived from the measured extent of the whole multi-line block and then multiplied by the line count again. It now measures a true single-line height, so multi-line boxes grow linearly (a 5-line note that auto-fit to 406 px now fits to 86 px; a 10-line note that hit the 600 px clamp now fits to 182 px). Single-line elements, labels, and paragraphs are byte-identical — only multi-line auto-fit changes. Latent since note/group auto-fit was introduced; it only surfaced when a caller omitted the height *and* the text contained explicit newlines.
- **Compound undo preserves child paint order and folder order.** Undoing a compound that deleted several sibling diagram objects or model elements (via `bulk-mutate` or a forced folder delete) restored full membership but scrambled the children's z-order and the model-tree folder order, because each delete captured an absolute insertion index and a compound undoes its members in reverse — so a later delete restored into a list whose earlier members were not yet back. Each removed item now records its surviving-successor sibling at delete time and, on undo, re-inserts directly before that anchor, falling back to the clamped absolute index only for a tail item. Single deletes and the common ascending-order multi-delete are exact; membership and connection integrity are always preserved.

## v1.7.0 (2026-06-18)

Security & hardening release. v1.7 hardens the server's trust boundary for the agent era: Origin/Host header validation **on by default**, **opt-in bearer-token authentication**, the TLS keystore password and the auth token moved out of the plaintext preference store into the **OS keychain** (Equinox secure storage), **request-size / idle-timeout / bounded-thread-pool** guardrails on the embedded Jetty server, **bounded remote-image downloads**, and **idle-TTL eviction** of per-session state — with the full responsibility boundary written down in a new top-level **`SECURITY.md`**. It also adds a human-owned mutation **approval queue** with a dockable desktop review surface (the agent can no longer un-gate itself), **scopes agent undo/redo** to the agent's own edits, and adds a build-from-source + CI safety net for the full test suite. Three tools were removed from the MCP surface — the legacy Zest `compute-layout` tool, and the two agent-side approval-control tools (the gate toggle and approve/reject, now human-only) — so the tool count is **69** (down from 72; resources unchanged at **14**).

### Features

- **Human-in-the-loop approval queue with a desktop review surface.** When approval mode is on, the agent's queued changes appear in a dockable **Pending Approvals** view inside Archi (open via **Window → Show View → MCP Server → Pending Approvals**, or the **MCP Server → `Pending approvals (N)`** menu item, which carries the live count). Each gated tool-call — a whole `bulk-mutate` included — is **one card** whose effect text is **server-generated from the model's own truth**, so you can decide Approve/Reject from the card alone without opening the raw JSON. Cards name what they touch: relationships name both endpoints (`Create ServingRelationship: 'Payment Gateway' → 'Fraud Engine'`), a delete names its endpoints plus the cascade (`Delete …: 'A' → 'B' (cascade: 2 view connections)`), visual changes name the **destination view** (`Add ApplicationComponent 'Mobile Banking App' to view 'Application Collaboration'`), and a `bulk-mutate` card's expanded rows are named per operation. An **icon encodes each concept kind** — `▢` model element, `↔` model relationship, `▣` placed node (visual object), `⇿` drawn connection — and destructive counts are called out in **amber** (colour means destructive only). **`Show changes`** expands a card to verb-prefixed rows (deletes hoisted to the top) with a `Technical details` disclosure of the raw parameters; **`Approve`** applies the change (a card containing a delete stays disabled until expanded once), **`Reject`** discards it with no change to the model. Toolbar **`Approve all safe`** clears purely-additive cards in one click and **`Approve all ⚠`** drains everything after one confirmation that names the deletion count; both go oldest-first. A queued change that the model has moved past since it was proposed is rejected as **stale** rather than applied blindly. New gated changes appear live, no refresh needed.

- **Optional `intent` parameter on `begin-batch` and `bulk-mutate`.** The agent can supply a plain-language "why" for a batch; when present it appears as a quiet, italic `agent's note:` line **below** the server-generated effect on the approval card — never replacing or outranking it, and **suppressed when hollow** (generic notes like "Updating the model" are dropped so vagueness never occupies the trust slot). Effect text is non-spoofable server ground truth; intent is a separate, lower-trust, suppressible claim — the two are never merged, and the server never depends on intent.

- **`resize-elements-to-fit` gains a `wrapFit` mode.** With `wrapFit: true` the tool keeps each element's width and grows only its height, so a long label wraps onto extra lines instead of being clipped or forced into an over-wide box — useful for nested labels in fixed-width containers. (After a parent grows to contain a wrapped child, follow with `auto-route-connections`.) Default behaviour is unchanged.

- **`get-view-contents` graph nodes and edges now carry their visual identifiers.** Nodes include a `viewObjectId` and edges a `viewConnectionId`, so a visual returned by a query can be fed straight into `remove-from-view`, `update-view-object`, or `update-view-connection` without a second lookup to resolve the visual id.

### Security

- **Origin/Host header validation, on by default.** The embedded server now rejects (HTTP 403) any request whose `Host` header — or `Origin`, when a browser sends one — is not a loopback name, closing the DNS-rebinding / malicious-web-page vector that could otherwise drive the MCP tools from a page in your browser. Enforced in front of both the `/mcp` and `/sse` transports. Zero configuration change for existing users: every localhost client (Claude CLI, Cline, `mcp-proxy`) already connects via `127.0.0.1` / `localhost` and is unaffected. Validation is relaxed automatically when you deliberately bind to a non-loopback address (that advanced case is governed by network/firewall and token controls instead).
- **Opt-in bearer-token authentication.** You can now require an `Authorization: Bearer <token>` header on every request. Enable it in **Window → Preferences → MCP Server → Authentication**: a 256-bit token is generated on first opt-in, stored in Equinox secure storage (the same OS-keychain-backed store Archi itself uses — no separate password), and shown with a **Copy** button and a **Generate / Regenerate** action. When enabled, both the `/mcp` and `/sse` transports reject any request with a missing, malformed, or wrong token with HTTP `401` (constant-time comparison; JSON-RPC error envelope; `WWW-Authenticate: Bearer` challenge). **Off by default — zero change for existing users** until you turn it on; if enabled but the token can't be read, the server fails closed (rejects everything) rather than serving unauthenticated. Composes with the Origin/Host validation above. See the README "Enabling authentication" section for client configuration (`claude mcp add … --header`, `mcp-proxy --headers`).
- An in-context exposure warning now appears on the preferences page when the server is bound away from `127.0.0.1`; once a bearer token is enabled, that warning softens to an advisory noting the exposure is mitigated (and recommending TLS so the token is not sent in cleartext).
- **TLS keystore password moved out of the plaintext preference store into Equinox secure storage.** When TLS is enabled, the keystore password is now stored encrypted in your OS keychain (the same store the bearer token and Archi itself use — no separate password to manage), instead of in cleartext in the workspace `.metadata` preference file where an automated secret scanner would flag it. The preferences field is now masked. Any keystore password set in an earlier version is migrated automatically and fail-safely on first start — read once, written to secure storage, and only then cleared from the plaintext store; if secure storage is unavailable (e.g. a locked or lost keychain), the old value is left untouched so TLS keeps working and the migration simply retries next start. No configuration change and no behaviour change for existing TLS setups.
- **Approval mode is now human-owned — the agent can no longer ungate itself.** A self-ungating safety control is a lie to the user, so the control plane has moved to the human and the agent's path to it no longer exists. The `set-approval-mode` (toggle) and `decide-mutation` (approve/reject) MCP tools are **removed entirely** from the surface — not guarded, removed, because the only robust guard is non-existence. The on/off toggle now lives in Archi (the checkable **MCP Server → Approval Mode** menu item), written only from the desktop UI; turning the gate *off* requires a confirmation, turning it *on* is a single click. Your setting is **remembered across restarts** (stored in MCP preferences); a fresh install defaults to **GATED** (fail safe). The agent keeps a **read-only** view of the mode (a new `approvalMode` field on `get-model-info`) and the read-only `list-pending-approvals` observation tool, so it can honestly tell you "you're gated — confirm in Archi" instead of silently failing. Approve/reject moves to a UI-callable service the desktop binds to. _(Together with the Pending Approvals view, this forms the full human-in-the-loop gate.)_
- **Agent undo/redo is scoped to the agent's own changes.** Agent-authored CommandStack entries are origin-tagged, and the `undo`/`redo` tools stop at — and refuse to cross — any human edit on the stack, so an agent can never silently revert your hand-drawn work (to reverse a human change it must submit a new proposal). Your own native `Ctrl+Z` in Archi remains unscoped and still undoes anything.
- **Request-size cap, idle timeout, and a bounded thread pool on the embedded server.** The embedded Jetty server now rejects oversized request bodies (~32 MiB cap, enforced on both declared `Content-Length` and actual streamed/chunked bytes) with HTTP `413` rendered as a JSON-RPC error envelope, drops connections idle past 120 s, and runs on an explicit bounded worker pool (8–50 threads) instead of the implicit default-200 pool. Closes the gap where a single giant request body could exhaust memory and take down Archi along with your unsaved model. The limits are fixed safety-bound constants, not preferences; no configuration or behaviour change for normal use.
- **Per-session state is now bounded by an idle TTL.** MCP sessions, their caches, and batch contexts were previously kept forever, so a client fabricating session IDs (or a long-running install) could leak memory without limit. Sessions and caches idle past a 24-hour TTL are now evicted on an opportunistic write-path sweep (no background thread); a batch's context is dropped when it ends, but only when no approval proposals are still pending, so the pending-approval queue is never silently discarded. Active sessions are never evicted mid-conversation, and the default session is never evicted.
- **Remote image downloads are now bounded before buffering.** When a tool fetches an image from a URL, the response is streamed into a single fixed buffer that aborts the instant it would exceed the 1 MiB cap, and an overall download deadline is enforced between reads. Previously the whole body was buffered *before* the size was checked, so a chunked or `Content-Length`-less oversized response — or a slow-drip "slowloris" body — could exhaust memory or pin a worker. Allocation is now bounded regardless of what the remote server sends.

### Changed

- **Approval mode is now a single global switch, not per-MCP-session.** Previously each MCP session carried its own approval flag; with one human owning one desktop gate, that is now one plugin-wide state — two concurrent sessions see the same mode. Pending proposals remain per-session. This is the only model consistent with a human-owned control plane.

### Removed

- **`compute-layout` removed.** The legacy graph-layout tool (Zest tree / spring / directed / radial / grid presets) is gone; its role is superseded by `auto-layout-and-route` (ELK Layered), which both positions elements and routes connections in one call. Removing it also resolves a startup failure on **Archi 5.10**, whose bundled graph-layout library otherwise made the entire MCP tool surface fail to load. This is the `72 → 71` part of the tool-count change.

### Fixes

- **Server startup failures are now self-diagnosable from the status message.** Two common desktop failures were previously reported as a generic `SERVER_START_FAILED`: a port-in-use error nested more than one level deep in the cause chain, and — under TLS — a keystore load failure that the pre-flight validation cannot catch (wrong password, or a corrupt/empty/wrong-type keystore file, since Jetty loads the keystore during start). They are now classified as `PORT_IN_USE` and `INVALID_TLS_CONFIG` respectively, reusing the existing error codes and status-message mapping, so you can tell *why* the server did not start without reading the log. A guard keeps unrelated runtime failures generic rather than mislabelling them. No manager, UI, or wire change.

- **`assess-layout` hub-port quality now reports the worst face, not the average.** The M5 hub-port-quality metric (HPQ) averaged across an element's connection faces, which let one badly-distributed face hide behind well-distributed ones; it now reports the minimum (worst) face, so a degraded hub is no longer mean-diluted in the score. This changes the HPQ value an agent reads back from `assess-layout` on hub-heavy views.

### Documentation

- **`SECURITY.md` — the responsibility boundary, made citable.** A new top-level `SECURITY.md` states what the server protects against by default (loopback bind, Origin/Host validation, request/session/image resource limits, the human-owned fail-safe-GATED approval gate, agent-scoped undo, secrets in the OS keychain) versus what is the operator's responsibility (transport encryption, client authentication, securing a non-loopback bind, the prompt-injection backstop, and the not-yet-allowlisted filesystem paths), with a trust-boundary diagram, a supported-versions note, and a private vulnerability-reporting process via GitHub Security Advisories.

- **`remove-from-view` now actually removes nested ArchiMate-element view-objects** — those placed inside another component, node, or group via `parentViewObjectId` — instead of silently doing nothing while still returning `{action: "removed"}`. The element-removal path now resolves the real immediate parent container, matching the group and note paths, so nested ghost view-objects no longer persist on the canvas, in `assess-layout`, or in the saved `.archimate` file. A postcondition guard now fires if the underlying removal does not take effect, converting any future regression into a structured `INTERNAL_ERROR` that names the parent and the object — rather than the previous silent no-op reported as success.
- **`auto-route-connections` now self-heals the "exit-then-return" terminal zigzag** — a connection that overshoots past its target's far edge and then doubles back to attach (for example, routing up past the top of a box, then down to its bottom face). Previously the reversal-elimination pass detected the overshoot but could remove a terminal anchor while collapsing it, which caused the terminal-anchor guard to roll the whole straightening pass back — so the cosmetic defect survived and only a full `auto-layout-and-route` re-layout could clear it. The pass now confines its collapse to the route interior, leaving both terminal attachment points byte-identical, so re-running `auto-route-connections` removes the overshoot in place. When a foreign element genuinely blocks the straightened corridor, the pass correctly declines and leaves the route untouched. Behaviour is unchanged for every route that did not carry this defect.

The tool description also clarifies the 0-indexed back-reference semantics. Both cases still reject with `INVALID_PARAMETER`; only the diagnostic text changes, so an agent can tell an operator off-by-one apart from a forward-reference mistake on the first response.

## v1.5.0 (2026-05-28)

Authoring completeness. v1.5 adds four new tools — `add-image-to-view` (place a standalone image as a diagram node), `add-view-reference-to-view` (embed one view inside another), `update-model` (write model name, purpose, and properties), and `find-concept-usage` (reverse where-used lookup before deletes and renames) — plus broader Archi-GUI styling coverage on view objects and connections (typography, gradient, alignment, line style, opacity), two new `export-view` formats (PDF and JPG, plus a real SVG instead of the previous stub), and a batch of routing and validation fixes. Validated end-to-end on a fresh 221-element reference model — 11 of 11 views rated good or better, 8 excellent. Tool count grows from 69 to **72**; resource count is unchanged at 14.

### New Tools

- **`add-image-to-view`** — Place a standalone image as a first-class diagram node on a view, sibling to notes, groups, and view-references. Distinct from the existing `update-view-object` `imagePath` parameter, which sets an icon overlay on an element. Requires `viewId` and `imagePath` (returned by `add-image-to-model` or `list-model-images`). Optional `x`/`y` (both-or-neither, parent-relative when `parentViewObjectId` is set), `width`/`height` (default: the image's natural dimensions read from the model archive; falls back to 200×200), and the full visual styling surface (fill / line / font colour, opacity, line width, line style, gradient, alignment, border type) plus image-specific `borderColor` and `documentation`. Typo'd `imagePath` values are rejected with the new `IMAGE_NOT_FOUND` error rather than silently rendering as a broken-image placeholder. Image visuals are bulk-mutate-callable and now round-trip via `get-view-contents` in a new `images` array.
- **`add-view-reference-to-view`** — Embed one ArchiMate view inside another as a clickable thumbnail — the agent-driven equivalent of Archi GUI's drag-view-onto-view. Useful for landscape views that embed each layer view, index views that link every viewpoint, and cross-cutting documentation views that reference detail views. Requires `viewId` (target) and `referencedViewId` (source — must be an existing ArchiMate view in the same model). Optional bounds, parent nesting, and the full visual styling surface. The referenced view's name is not stored on the visual; Archi reads it dynamically at render time, so renaming the referenced view via `update-view` updates every embedding automatically.
- **`update-model`** — Write the loaded model's own `name`, `purpose`, and custom `properties` as a single undo unit (mirrors the shape of `update-view`). At least one of the three must be provided; omitted fields stay untouched. Empty-string `purpose` clears the field; null property values remove a key. Archi 5.7/5.8 exposes a single free-text field on the model — `purpose` — so there is no separate `documentation` parameter. `bulk-mutate` accepts `update-model`.
- **`find-concept-usage`** — Reverse where-used lookup: given an element or relationship ID, returns every view and every visual object or connection that references it across the model. The inverse of `get-view-contents`. Intended for impact analysis before `delete-element`, `delete-relationship`, rename, or re-type workflows — one round-trip reveals the full cross-view footprint. Placements are grouped by view; each view carries a `viewKind` (`archimate` / `sketch` / `other`) plus `viewReferenceCount` and `visualReferenceCount`. Views are ordered by name, visual objects by ID — deterministic regardless of underlying iteration order.

### Read / Write Parity

- **`get-model-info` now returns `purpose` and `properties`** — read-side companion to `update-model`. Existing callers see byte-identical responses on default-state models; the new fields appear only when set.
- **`list-specializations` now returns `imagePath`** — surfaces the archive path of the specialization's icon when one is set; omitted otherwise.
- **`get-view-contents` now returns an `images` array** — image visuals (placed via `add-image-to-view`) round-trip on view reads. The DTO carries the visual's ID, image path, bounds, parent, border colour, and documentation.

### Existing Tools Extended

- **Relationship semantic attributes on `create-relationship` and `update-relationship`** — three new type-conditional optional parameters fill out ArchiMate semantics that the create/update path previously could not set:
  - `accessType` (AccessRelationship only) — enum: `"access"` (unspecified), `"read"`, `"write"`, `"readwrite"`.
  - `associationDirected` (AssociationRelationship only) — boolean.
  - `influenceStrength` (InfluenceRelationship only) — free text, max 255 characters; empty string clears.

  Supplying a parameter on the wrong relationship subtype is rejected at the boundary with a `suggestedCorrection` naming the valid type. The three fields populate on the response DTO only when the relationship is of the matching subtype, so JSON shapes for relationships of any other type are unchanged. The new fields automatically appear on every read surface (`get-relationships`, `search-relationships`, `get-view-contents`, `find-concept-usage`).
- **Specialization icons on `create-specialization` and `update-specialization`** — both tools accept an optional `imagePath` (an archive path from `add-image-to-model` or `list-model-images`). When set, Archi renders this image as the specialization's icon on every element or relationship of that specialization. `update-specialization` also accepts `clearImagePath: true` to explicitly clear the icon (mutually exclusive with `imagePath`). `update-specialization` has relaxed `newName` from required to optional — at least one of `newName`, `imagePath`, or `clearImagePath` must now be supplied.
- **`update-view-object` `labelExpression`** — `add-to-view` and `update-view-object` accept an optional per-view-object dynamic label template, e.g. `"${name}"` or `"${property:Owner}"`. Distinct from the literal stored `text` label; empty string clears.
- **Full styling completeness on view objects and connections** — `add-to-view`, `add-group-to-view`, `add-note-to-view`, and `update-view-object` accept optional typography (`fontName`, `fontSize`, `fontStyle`), `gradient` (`none` / `top-bottom` / `bottom-top` / `left-right` / `right-left`), note-specific `borderType` (`dogear` / `rectangle` / `none`), `deriveLineColor`, `outlineOpacity`, and `lineStyle` (`solid` / `dashed` / `dotted` / `none` — the outline border style of the view object itself). `add-connection-to-view` and `update-view-connection` accept the typography fields. All fields ride the existing styling rail as a single undo unit; existing calls are byte-identical and the new fields read back on the mutation response DTOs.
- **`add-to-view`, `add-group-to-view`, `update-view-object` `figureType` and `textAlignment` / `verticalTextAlignment`** — `figureType` (`rectangular` / `tabbed`) overrides Archi's default group tab; `textAlignment` and `verticalTextAlignment` control label position within the figure. These shipped in v1.4 but are now also accepted on `update-view-object` for consistency.
- **`export-view` PDF, JPG, and a real SVG** — `export-view` now accepts `format: "pdf"` (vector, print-ready) and `format: "jpg"` (lossy raster) in addition to `png` and `svg`. A new optional `quality` parameter (1–100, default 90) controls JPEG encoding quality; it is silently ignored for other formats. The previous "not yet supported" stub on `format: "svg"` is replaced with a real SVG XML export. Vector formats (SVG, PDF) leave `width`/`height` null because they are resolution-independent. PNG behaviour is byte-identical. SVG and PDF require the `com.archimatetool.export.svg` bundle (ships with Archi 5.7+); on a stripped Archi install only SVG and PDF emit `FORMAT_NOT_AVAILABLE`, the rest of the plugin still loads.

### Fixes

- **`add-to-view` and `update-view-object` now reject typo'd `imagePath` values with `IMAGE_NOT_FOUND`** — closing the gap between these surfaces and `add-image-to-view`. Previously, a typo'd archive path on `add-to-view` or `update-view-object` (also via `bulk-mutate`) was accepted at the prepare boundary and rendered as a broken-image placeholder downstream, with no error envelope for the agent to act on. The validator added in v1.5 for `add-image-to-view` / `create-specialization` / `update-specialization` is now wired into the four `add-to-view` / `update-view-object` prepare paths, producing the byte-identical `IMAGE_NOT_FOUND` reject payload across all three tool surfaces. Empty-string `imagePath` on `update-view-object` remains the documented "clear the icon" sentinel and is not validated.
- **`auto-connect-view` now skips connections between an ancestor and its descendant on the view** (which would render as a self-pass-through), reporting them under a new `skippedDueToNesting` field on the response DTO. The model relationship is preserved; the agent can choose to draw it explicitly via `add-connection-to-view` if desired. This closes a gap where the tool was creating exactly the `M4 connectionEdgeCoincidence` defect class that `assess-layout` is built to catch. Sibling-pair, cross-branch, and flat-view behaviour are unchanged.
- **`auto-route-connections` now surfaces autoNudge-blocked recommendations under a new `blockedRecommendations` field with a top-level `nudgeBlockedReason` (`"sibling_overlap"`), reserving `recommendations` for the advisory (`autoNudge=false`) path.** Previously, an `autoNudge=true` call against a view with overlapping sibling elements returned `recommendations` populated AND `nudgedElements` empty — a mixed signal the agent had to disambiguate via `structuredWarnings`. The underlying refuse-to-nudge behaviour is unchanged; the `AUTO_NUDGE_SKIPPED_SIBLING_OVERLAP` structured warning continues to emit in parallel.
- **`delete-view` now cascades view-reference visual placeholders correctly** — when a view that was embedded in other views (via `add-view-reference-to-view`) is deleted, the visual placeholders pointing at it across the rest of the model are now removed atomically with the view, mirroring Archi GUI's tree-delete cascade. Without the cascade, the EMF cross-reference stayed resolvable in-memory (so the live MCP session saw no problem) but `.archimate` save+reload wrote a dangling reference and Archi could not reopen the file with an "Unresolved reference" error. Reproduced against a real model on 2026-05-27. Latent in `delete-view` since v1.0 but only newly exploitable in v1.5, because v1.5 added the first MCP path to *create* view-reference visuals. Placeholders contained inside the view being deleted are correctly skipped (they die with the view).
- **`auto-route-connections` source-side reversal on lane-crossing hand-off** — when a connection crossed a swimlane boundary at a hub or anchor, the late-stage terminal-egress clearance passes treated the endpoint's ancestor container as an obstacle, occasionally reversing the source-side terminal segment. The clearance passes now mirror A*'s ancestor-exclusion rule, so the endpoint container is no longer in the obstacle set during clearance — the connection routes from the inside of its container out, matching the GUI's manual-routing result.
- **`auto-route-connections terminals-only` mode interior-termination and zigzag vetoes** — the terminals-only rectification no longer leaves a route in a worse state than it found it. A rectification that would introduce an interior termination or convert a clean L-bend into a zigzag is now vetoed and the original terminal is preserved.
- **`get-view-contents format: "graph"` no longer crashes on views with groups or notes** — the graph-format converter was assuming every view object was an element-bearing node, and threw on groups and notes. It now emits them as the documented graph nodes.
- **`bulk-mutate` operation-cap contract reconciled** — the `operations` array's own parameter description advertised "Max 50 operations" while the schema, the tool-level description, and the enforced limit all said 150 (the limit was raised in v1.2). Agents read the param description closest to the array and self-throttled to ~48-op batches. Both surfaces now derive the cap from the same constant. No behavioural change — the enforced limit was, and remains, 150.
- **`bulk-mutate` supported-tools list completed** — the tool advertised two incomplete supported-tools enumerations: the parameter description named 10 of 24, and the tool-level description named 12 — both omitting high-value mutations like `delete-element`, `update-relationship`, `update-view`, and the folder and specialization tools. An agent reading either list could wrongly conclude those tools were not bulk-callable. Both descriptions now derive from the same source of truth and list every supported tool. No behavioural change.
- **`update-view-connection` no longer falsely reports "Connection bendpoints cleared" on styling-only updates** — the next-steps message now distinguishes bendpoints-cleared, bendpoints-set, and styling-only changes accurately.

## v1.4.0 (2026-05-21)

Routing-perception cycle. v1.4 reworks how layout quality is *measured* so the rating reflects what an architect actually perceives, and lifts the LLM-facing precondition surface so an agent can set a view's geometry up correctly *before* routing. Tool count grows from 65 to 69; resource count grows from 7 to 14. The metric acronyms used below — M1–M6, R8, `parallelConnectionGap_V_p10`, HPQ — are defined in the [glossary](docs/glossary.md).

v1.4 delivers improved layout and routing compared to v1.3, validated end-to-end by an LLM agent driving the tools to build a comprehensive multi-view reference model.

### New Tools

- **adjust-view-spacing** — Inflate inter-element and inter-group spacing on an existing view, then re-route, in a single atomic operation. Use it when a view is laid out correctly but looks cramped, without re-running layout from scratch and losing manual placement.
- **apply-element-spacing-recommendations** — Widen within-group element spacing until the view reaches good quality, is honestly flagged as needing a structural reflow, or the iteration budget runs out. Runs an internal control loop — take a small step, re-assess, then continue, escalate, or stop — and reverts any step that makes things worse. Returns before/after `assess-layout` snapshots plus `terminationReason`, `iterationCount`, and `appliedDeltas`. Set `dryRun: true` to preview. One call is one undo step.
- **apply-group-spacing-recommendations** — The same control loop applied to inter-group corridors only, preserving group order and topology.
- **apply-spacing-recommendations** — Runs both arms (element, then inter-group) in one transactional call. The `scope` parameter (`both` / `element` / `group`) selects which arm(s) run. Per-iteration step caps prevent over-inflation; per-arm termination reasons, iteration counts, and applied deltas are reported.

### Routing Preconditions (LLM-Facing Surface)

A precondition is a property of the view's geometry that must hold *before* routing — the pipeline can refine routes but cannot create hub sizing, spacing, or group arrangement. v1.4 makes the three load-bearing preconditions first-class.

- **Control loop with density-aware termination** — The three spacing tools no longer apply one delta and return; each iterates internally and stops honestly. A step that degrades the view is always reverted, so the tool never returns a silently-worse view.
- **Sound infeasibility certificate** — When a view is provably too dense for spacing to fix, the tool stops, reports the reason, and offers a user-consentable structural reflow instead of churning. It never reflows on its own — a reflow moves user-placed elements, so it is the user's decision.
- **`archimate://prompts/routing-preconditions-checklist` (new resource)** — The single checklist an agent fetches before `auto-route-connections` or `auto-layout-and-route` on a non-trivial view: three preconditions, one verification each, plus a matrix mapping view shape to precondition order.
- **Density-aware defaults** — `arrange-groups` and `adjust-view-spacing` derive a connection-count-aware spacing default when none is supplied, instead of a static value. Pass an explicit value to suppress.
- **`assess-layout` names the fix** — When the assessment finds a violation that maps to a precondition (low hub-port quality, edge-coincident segments on a grouped view, children outside a parent's bounds), the `nextSteps` envelope names the right tool and attaches the violator IDs.
- **Structured warnings on `auto-route-connections`** — The response carries a machine-readable `structuredWarnings` list (`code`, `message`, `remediationTool`, `remediationViolatorIds`) alongside the free-text warnings, so an agent can act deterministically.

### Assessment (Perception-Aligned)

`assess-layout` gains metrics for defect classes the old assessor could not see. See the [glossary](docs/glossary.md) for each metric and the [Layout Engine](docs/layout-engine.md) doc for thresholds.

- **New metrics** — M2 interior terminations, M3 zigzag/reversal, M4 connection-vs-edge coincidence, M5 hub-port quality (HPQ), and R8 corridor utilisation. M1 (non-orthogonal terminals) is corrected to count only the visible portion of a diagonal, ending an over-report.
- **Two-dimensional rating (M6)** — The overall rating now reports `(layoutTier, routingTier)` and takes the worse of the two, so a routing fix on a well-laid-out view no longer drags its layout tier down.
- **Re-anchored cut-points** — Any sibling overlap now caps the layout tier at `poor`, and a parent label obscured by a child is promoted into the rating — both align the score with the perception that a single visible defect reads as a broken view.
- **Informational narrow-corridor signal** — `parallelConnectionGap_V_p10` surfaces when a view is in the narrow-corridor regime, so an agent can recognise that spacing tools cannot help and the remedy is structural. It does not affect the rating.
- **Classification precedence** — A connection already flagged as a pass-through is no longer also double-counted as a zigzag.
- **Density-aware non-orthogonal scoring** — Non-orthogonal terminals are scored by ratio rather than raw count (so connection-heavy views are not over-penalised) and treated as cosmetic, reflecting that diagonal terminals rarely affect comprehension.

### Tool Surface Additions

- **Group and element styling** — `add-to-view`, `add-group-to-view`, `add-note-to-view`, and `update-view-object` accept `figureType` (`rectangular` / `tabbed`), `textAlignment`, and `verticalTextAlignment`. These close v1.3 feedback that groups were always tabbed and labels always centred. Additive and non-breaking; existing calls are unchanged, and the new fields read back on `get-view-contents`.
- **Hub 2D-resize suggestion** — For elements with more than 12 connections, `detect-hub-elements` also suggests a two-dimensional resize so ports can spread across all four edges, not just one.
- **Hub-aware spacing** — The spacing tools select a wider spacing tier when a view contains hub elements, since formula-sized hubs consume corridor space.

### Layout Fixes (vs v1.3)

- **Text boxes reserve room for their text** — `add-note-to-view` and `add-group-to-view` size the box to fit wrapped content when the caller does not pin a height, so descriptive titles and long group labels no longer clip. Explicit sizes are unchanged; heights clamp to documented maxima.
- **Containers reserve their icon corner** — A container that carries a corner-anchored icon grows enough to keep the icon clear of nested children, preventing the icon-on-child overlap. Containers without an icon are unchanged.
- **`arrange-groups` reserves a lane for standalone hubs** — Topology row/column arrangement now centres a top-level element that connects across multiple groups in an inter-group lane between its neighbours, delivering the "place it between the zones" layout the viewpoint recipes describe.
- **Parent groups resize to contain their children** — A child moved outside its parent group's bounds now triggers a parent resize, across all three paths that can move a child (auto-nudge, the spacing tools, and direct object update). Closes a long-standing defect where a group was left too small for its contents.

### Routing Fixes (vs v1.3)

- **Self-element pass-throughs resolved** — A connection whose route looped back through its own source or target is now corrected algorithmically. This closes a user-visible issue present since v1.0.
- **Terminals-only routing mode** — `auto-route-connections` accepts `mode: "terminals-only"`, which rectifies only the diagonal terminal segments of automatic-layout output without re-routing whole connections — avoiding the crossing inflation a full re-route causes on that input.

### Routing Pipeline Improvements (vs v1.3)

These pipeline improvements deliver better routing than v1.3 across the reference views, and are protected by regression tests:

- Seeded multi-start routing — picks the best of several candidate routes, and is never worse than the single-shot route by construction.
- Hub-perimeter and terminal-segment corridor handling for multi-bendpoint routes.
- Channel-global ordered nudging that spreads parallel segments across whole channels, including inter-group corridors.
- An invariant that locks a connection's perimeter-terminal face through the whole pipeline, preserving hub-port distribution end-to-end.

### Viewpoint Recipes

- **Recipe library (six new resources)** — A progressive-disclosure library under `archimate://recipes/*`. Fetch `archimate://recipes/index` first; it states the build sequence once, routes conventional viewpoints to the existing view-patterns principles, and points non-conventional viewpoints (application integration, behaviour/process flow, motivation, technology deployment, roadmap/migration) to a single recipe page with a topology block to match.
- **Element-type and nesting guidance** — The view-patterns and layers references are sharpened so an agent picks the right element type (Component vs Service, Process vs Function, Node vs Component, Actor vs Role) and nests structural parts instead of drawing a redundant Composition or Aggregation connector. These target recurring v1.3 reports of wrong element type and drawn-instead-of-nested composition.

### Quality Protection

Every quality threshold introduced in v1.4 ships with a regression test that pins it against the manual-routed reference, so a future change that regresses a metric fails a test instead of silently shipping. See [Layout Engine — JUnit-Protected Release-Gate Metrics](docs/layout-engine.md).

- **New: [glossary](docs/glossary.md)** — Defines every metric acronym, routing term, and rating tier in one place.
- **New: bibliography** — A numbered research bibliography for the layout engine and routing pipeline, with a per-stage citation map and a separate modelling/visual-design reference subsection backing the LLM-facing guidance.
- **Updated** — The routing-pipeline and layout-engine docs cover the assessor redesign, the control loop and infeasibility certificate, and the pipeline groundwork. The README catalogs all 69 tools, the new metrics, and the new resources. Tool descriptions are swept so an agent gets the full spacing and routing contract from the tool surface alone, with external guidance pointing to the MCP resources.

## v1.3.0 (2026-04-10)

Expressiveness cycle. Adds first-class support for ArchiMate **specializations** (IS-A subtypes of element and relationship types) across the read, write, search, and resource surfaces. Tool count grew from 60 to 65. Also bundles a batch of layout, assessment, and routing-quality enhancements discovered during E2E validation runs.

### New Tools

- **list-specializations** — List every specialization defined on the model with `(name, conceptType, layer, usageCount)`. Optional `conceptType` filter narrows the result to a single concept binding.
- **create-specialization** — Define a specialization explicitly without creating any element. Idempotent — returns the existing specialization on duplicate `(name, conceptType)`. Use this to pre-register a vocabulary at session start.
- **update-specialization** — Rename a specialization. Refuses to merge into an existing target name (collision-rejecting). Existing references on elements and relationships move with the rename.
- **delete-specialization** — Remove a specialization. Refuses by default if any concept uses it; pass `force: true` to detach all references and delete in one atomic command. Refuses force-delete on concepts that carry more than one specialization (clear the extras first).
- **get-specialization-usage** — Pure query. Lists every element and relationship referencing a specialization. Call before rename or delete to audit the blast radius.

### New Capabilities

- **Inline specialization on element and relationship mutations** — `create-element`, `create-relationship`, `update-element`, and `update-relationship` accept an optional `specialization` parameter. On create, the specialization is auto-created if missing — the element/relationship and the specialization land in one CompoundCommand (single undo unit). On update, pass an empty string `""` to clear all specializations from the concept. Source, target, and type remain immutable on relationship updates.
- **Specialization filter on search** — `search-elements` and `search-relationships` accept a `specialization` filter that returns only concepts of the given specialized type. Combines with existing `type`, `layer`, and text filters.
- **specializationCount on `get-model-info`** — Model overview now reports the total specialization count. Non-zero means the model uses a custom vocabulary; call `list-specializations` to browse it.
- **`specialization` field on `ElementDto` and `RelationshipDto`** — Query responses now expose the primary specialization name on every element and relationship DTO. (See "Multi-Profile Caveat" in the new resource for the single-primary semantics.)
- **Connection styling on `auto-connect-view`** — `auto-connect-view` accepts `lineColor`, `fontColor`, and `lineWidth` parameters, applied uniformly to every connection it creates. Combines with `relationshipTypes` to batch-style connections by relationship type in a single call (e.g. blue for API calls, orange for domain events).

### Routing Pipeline Improvements

- **Self-element pass-through rating tolerance** — Self-element pass-throughs (a connection's route entering its own source or target through an interior point rather than from an edge) no longer penalise the overall layout quality rating. Cross-element pass-throughs still penalise as before. Informational reporting is preserved for both types — `assess-layout` still surfaces the count, but the rating reflects only structurally meaningful violations.

### Layout Improvements

- **Containment-aware dynamic label height in `resize-elements-to-fit`** — Replaces the fixed 25px containment top margin with a per-parent label height computed from SWT font metrics and word-wrap simulation. When a parent element wraps its label across multiple lines, children are shifted down to clear the full label height instead of being obscured by the lower lines. Parent height never shrinks during the operation — only grows to accommodate the wrapped label and its children.
- **Element-count heuristic for grouped layout intra-group arrangement** — `auto-layout-and-route` with `mode: "grouped"` and `optimize-group-order` now choose intra-group arrangement based on element count and flow direction. For vertical flow (DOWN/UP): 1-3 elements arrange as a row, 4+ elements arrange as a grid. For horizontal flow (RIGHT/LEFT): column arrangement is preserved. Replaces the previous hardcoded column arrangement that produced 1:12 aspect ratio strips on vertical-flow grouped views.

### Assessment Improvements

- **Violator IDs for targeted fixes** — `assess-layout` accepts a new optional `includeViolatorIds` parameter (default `false`). When enabled, the response includes a `violatorIds` map keyed by metric name, each containing the list of visual object IDs that violate that metric. Supported metrics: `overlaps` (both element IDs per pair), `passThroughs` (connection IDs, cross-element only), `coincidentSegments` (connection IDs sharing corridors), `nonOrthogonalTerminals` (connection IDs with diagonal entry), and `boundaryViolations` (child IDs outside parent bounds). Crossings are excluded as an emergent property best addressed by global tools. The complete ID set is returned (no cap), enabling surgical per-element fixes without full re-layout.
- **Informational containment overlap suggestion** — When `assess-layout` reports containment overlaps (ancestor-descendant nesting), the suggestions list now includes an explicit informational note clarifying these are expected overlaps that need no action. Previously, the bare counter caused LLM consumers to interpret grouped views as broken.
- **Informational detections in `assess-layout`** — Three new detections appear in the assessment output but do not affect the overall rating:
  - **Label truncation** — word-wrap-aware vertical overflow check identifies elements whose label rendering exceeds the element bounds.
  - **Parent label obscured by child** — flags parent elements whose label area is overlapped by a child element. (Notes are excluded from this check.)
  - **Image sibling overlap** — flags elements with custom images that visually overlap sibling elements at the same containment level.
  These detections give LLM agents actionable signals to fix label and image quality issues without breaking the severity-tiered rating system.

### Bug Fixes

- **Bulk specialization profile deduplication** — Fixed a data-integrity bug where `bulk-mutate` creating multiple elements with the same new specialization (e.g. 8 `ApplicationComponent` elements all with `specialization: "Cloud Platform"`) produced duplicate specialization profiles — one per element in the batch — instead of sharing a single profile. Downstream operations were affected: `update-specialization` (rename) only renamed 1 of N references, `delete-specialization` only removed 1 of N, and `get-specialization-usage` understated impact. Root cause: bulk-mutate runs all prepare methods before dispatching any commands, so `resolveOrCreateProfile` could not find profiles created by earlier (not yet executed) operations in the same batch. Fix introduces a `ThreadLocal` bulk profile cache scoped to `executeBulk`, consulted before model lookup. Single-call (non-bulk) paths are unaffected.

### Routing Pipeline Improvements

- **Clearance-weighted A* routing** — A* cost function includes perpendicular clearance penalty (`clearanceWeight / max(clearance, 1.0)`, default weight 75.0) that steers the router toward open space. `computePerpendicularClearance()` measures distance from each graph edge to the nearest obstacle boundary. E2E result: crossings -41%, pass-throughs eliminated on test views.
- **Post-routing path straightening** — New `PathStraightener` class applies four correction passes after routing: snap-to-straight alignment for near-aligned segments, direction reversal elimination, staircase jog collapse, and redundant bend removal. Terminal anchors are protected throughout.
- **Post-simplification path shortcutting** — Late-stage greedy simplification (Stage 4.7g) finds farthest reachable point via straight line, horizontal-first L-turn, or vertical-first L-turn. Terminal bendpoints preserved as chain anchors. E2E result: crossings -27%.
- **Post-simplification coincident segment resolver** — Redesigned from endpoint-based (~350 lines) to corridor-based reuse of `CoincidentSegmentDetector` (~12 lines). Catches coincidences introduced by all post-processing stages. E2E result: coincident segments -50%.
- **Proportional corridor spacing** — Replaced fixed 10px offset delta with proportional gap distribution. Three-pass architecture: collect corridor groups, compute perpendicular gap via obstacle scanning, distribute segments proportionally with 8px minimum separation floor. Falls back to fixed-delta when corridor is too narrow. E2E result: coincident segments -80%.
- **Exterior perimeter routing** — Split obstacle clearance (10px) from perimeter boundary margin (50px), enabling routes to travel around the outside of element clusters. E2E result: routing success 12% to 100%.
- **Pass-through-aware face selection** — Phase 1.3 in `EdgeAttachmentCalculator` builds trial paths with current face assignments and checks for self-element pass-throughs. When detected, tries alternative faces in angular proximity order. Phase B re-routes terminal segments after face swap. E2E result: pass-throughs -75%.
- **Router corridor re-route** — Stage 5a re-routes failed connections (element crossings) using fresh A* search with the full pipeline cleanup sequence.
- **Terminal approach direction** — Phase 1.2 in `EdgeAttachmentCalculator` prefers natural entry direction for nearly-aligned elements (dominant axis > 2x minor axis). Hub elements excluded to preserve distributed port allocation.
- **Self-element pass-through correction** — Two-phase fix: face swap + comprehensive face selection with trial path validation. Safety net re-run of `correctEndpointPassThroughs()` retained as defense-in-depth.
- **Corridor directionality penalty** — Cosine-based `computeCorridorDirectionalityCost()` penalizes A* edges that move perpendicular or away from the target (`directionalityWeight * (1 - cos(angle)) / 2`, default weight 30.0). Steers connections toward direct approach paths. E2E result: non-orthogonal terminals reduced from 33 to 2 on Application Collaboration view.
- **Clearance cap** — `MAX_EFFECTIVE_CLEARANCE` (60px) caps the clearance benefit to prevent exterior corridors with unlimited space from becoming artificially attractive ("perimeter suction"). Clearance cost formula: `clearanceWeight / max(min(clearance, 60), 1.0)`.
- **Group-wall clearance cost** — `computeGroupWallClearance()` measures perpendicular distance from A* edges to the nearest group boundary. Edges running inside groups (close to group walls) are penalized, steering the router toward inter-group gaps rather than inside-group-wall corridors. Uses the same clearance weight and MAX_EFFECTIVE_CLEARANCE cap as obstacle clearance.
- **Center-termination fix** — Stage 4.7k `fixCenterTerminatedPath()` detects bendpoints at exact element center coordinates (zero-length ChopboxAnchor ray → visual center termination) and repositions them 1px outside the correct edge face midpoint. Applied twice: after edge attachment and as defense-in-depth after cleanup.
- **Post-nudge center-termination gap** — Re-runs `fixCenterTerminatedPath()` after edge nudging to catch center-terminations introduced by nudge position shifts.
- **Interior terminal BP fix** — Stage 4.7m `fixInteriorTerminalBPs()` detects and fixes all bendpoints inside source/target element bounds (not just at exact center). Terminal BPs are repositioned to edge face midpoints; intermediate interior BPs are removed. L-bends are inserted where repositioning breaks orthogonality.
- **Post-pipeline orthogonality enforcement** — Stage 4.7n `enforceOrthogonalPaths()` detects diagonal segments remaining after all processing and inserts horizontal-first L-turn bendpoints to restore orthogonality. Catches edge cases where cleanup stages remove BPs without reinserting L-bends.
