# Glossary

This glossary is the single source of truth for the metric acronyms (M1–M6, R8, `parallelConnectionGap_V_p10`), routing terms, and rating tiers that appear in tool descriptions, MCP resources, the [README](../README.md), and the rest of the technical documentation. When a term is used elsewhere without a definition, look it up here.

## Layout-quality metrics

`assess-layout` reports these metrics. Each one names a specific, perceptible defect class so an LLM agent can act on it directly. For the full rating model and thresholds, see [Layout Engine — Assessor Redesign](layout-engine.md).

| Metric | Result field | What it measures |
|---|---|---|
| **M1** | `nonOrthogonalTerminalCount` | Diagonal connection segments at an element terminal. The metric counts only the *visible* portion of the segment, so diagonals that Archi clips inside an element's bounds are not over-reported. |
| **M2** | `interiorTerminationCount` | Connections whose endpoint lands *inside* an element's body instead of on its perimeter face. |
| **M3** | `zigzagCount` | Route shapes that backtrack or reverse along an axis. A connection already classified as a pass-through is not also counted as a zigzag. |
| **M4** | `connectionEdgeCoincidenceCount` | Connection segments running parallel to, and within a few pixels of, another element's edge — so the line reads as if it is stuck to the box. The informational `edgeCoincidenceGrazedElementCount` / `edgeCoincidenceGrazedElements` enumerate *every* distinct grazed `(connection, element)` pair; the rating-bearing `connectionEdgeCoincidenceCount` and its connection-id `edgeCoincidence` key are byte-identical, fired once per connection via a `legacyFlagged` guard. |
| **M5** | `hubPortQualityScore` (**HPQ**) | How evenly a hub element's connections are distributed across its perimeter faces, scored 0–1. A low score means many connections collapse onto one attachment point. |
| **M6** | `(layoutTier, routingTier)` | The two-dimensional overall rating — see [Rating tiers](#rating-tiers) below. |
| **R8** | `corridorUtilisationScore` | How well wide corridors carry connections in proportion to their width, scored 0–1. |
| **`parallelConnectionGap_V_p10`** | `vAxisParallelGapP10` | Informational only (no rating impact). The 10th-percentile gap between parallel connection segments on the vertical axis, in pixels. A small value signals the narrow-corridor regime, where more spacing cannot help and the remedy is structural. |
| **Hub-to-neighbour crowding** | `hubNeighbourClearanceMin` | The smallest clearance, in pixels, between a hub element's edge and the row of spoke neighbours packed against it (measured only on a hub face carrying ≥ 3 overlapping spoke neighbours; `-1.0` = no measurable hub). Rating-affecting: a value below the 60 px crowding floor caps the layout tier, so a hub enlarged until it crowds its neighbours cannot rate `good`. |
| **Connection-through-note/image** | `connectionThroughNoteCount` | Connections whose route runs through a note's box or an element's rendered image rectangle. Rating-affecting (routing tier, Tier-3R, binary presence): any nonzero count caps the routing tier at `good`. Complements `connectionPassThroughs` (which the routing tier takes the worse of, so no double penalty). The **note** half is also disclosed by `auto-route-connections` on the call that applies the route, as `CONNECTION_ROUTED_THROUGH_NOTE`, from the same shared geometry; the image half is reported here only. |
| **Non-orthogonal interior segment** | `nonOrthogonalInteriorSegmentCount` | M1 extended from the terminal segments to the route interior: an off-cardinal (> ~5°) segment between the two terminal segments. Rating-affecting (routing tier, Tier-2R, ratio-bucketed like M1 and combined with it by the worse). |
| **Off-face parallel terminal** | `offFaceParallelTerminalCount` | A connection whose terminal route *departs* an element face then runs parallel to and hugging it — the first exterior segment travels along the departed face within 8 px of it. Rating-affecting (routing tier, Tier-2R, **binary presence** — any nonzero count caps the tier at `fair`; ratio-bucketing would let a low-ratio hug still read `good`). Deliberately **not** part of the accepted-cosmetics carve-out, so it caps `overallExcludingAcceptedCosmetics` too. Closes a blind spot in the M1 angular check, where a sub-pixel-off exit stub is below the visible-length threshold and so is not reported even though the parallel hugging trunk is plainly visible. It is the oracle the router's terminal egress-clearance work drives to zero; when the router reports `EGRESS_LIFT_LAYOUT_BOUND` the hug is layout-bound and the remedy is spreading the elements. |
| **Coincident face port** | `coincidentFacePortCount` | An element face on which two or more connection terminals collide onto the *same* perimeter port (within ~1 px along the face axis), so two edges appear to leave one point. Informational only (no rating impact). Closes a blind spot in M5 (`hubPortQualityScore`), whose per-face guard only scores a face carrying four or more connections — so a face with two or three coincident terminals reads a vacuous `1.0` despite the collision. It is the oracle the router's coincident-port dissolution pass drives to zero. Distinct from `coincidentSegmentCount` (two *connections* overlapping in a corridor) and from HPQ (*even distribution* across faces). |
| **Anchor drift** | `anchorDriftCount` | A connection whose stored route no longer matches the geometry it was computed for. Archi stores every bendpoint twice — once relative to the source centre, once relative to the target centre — and both describe the same absolute point at the moment the route was written, so moving or resizing an endpoint afterwards leaves the two reconstructions disagreeing by however far the element travelled. Flags above a 1 px representable-precision floor (a bendpoint offset is stored as an integer against a centre that is half-integral on an odd width, so each of the two reconstructions carries an independent ±0.5 px rounding error). Informational (no rating impact). **Not a route-shape defect**: the stored shape was correct when written, so no shape-based dimension can see it and no straightener can repair it — the remedy is to re-route the connection. |
| **Lateral-jog reversal** | `lateralJogReversalCount` | A connection that doubles back through a sidestep too narrow to be routing around anything: a four-point window whose two outer arms run in *opposite* directions along one axis, separated by a perpendicular jog of at most 8 px (mirroring `OFF_FACE_MIN_STUB_PX`, the clearance that already separates a hugging exit from a legitimate one). Informational (no rating impact). Distinct from M3 `zigzagCount`, which needs three consecutive points sharing *one* axis: the sidestep puts the two arms on two parallel lines, so no triple in the window shares an axis and the zigzag test cannot express the shape at any tolerance. Never double-counted — a connection already reported as a pass-through or a zigzag is skipped. |
| **Redundant bendpoint** | `connectionRedundantBendpointCount` | A bendpoint lying on — and between — its neighbours along a *horizontal or vertical* run, so removing it would not change the rendered orthogonal route (an axis-aligned collinearity test, not any-angle). Informational (no rating impact). Near-collinear *diagonal* micro-jogs are excluded (removing them would diagonalise an orthogonal segment), and router-pinned terminal egress-stub ports (a first/last bendpoint on its element's perimeter face) are excluded because a full re-route keeps them — so a nonzero count is a genuinely collapsible *interior* point that a `terminals-only` re-route removes. Distinct from M3: a collinear out-and-back spike is a zigzag, not a redundant point. |
| **Container fill equals child** | `containerFillEqualsChildCount` | A container whose *authored* fill colour equals a nested child's, so parent and children merge into one flat block. Informational (no rating impact). Backstop for the auto-recede backdrop, which already handles unauthored fills. |
| **Connection grazes visual** | `connectionGrazesVisualCount` | A connection touching or clipping a note's or image's *border band* — the outer strip the through-visual interior test discards — including a visual too small to inset. Informational (no rating impact). Disjoint from `connectionThroughNoteCount`: a crossing is classified as exactly one of *through* or *graze*. |
| **Label on note** | `labelOnNoteCount` | A connection *label* (not its route) rendered on a note's rectangle — the caption collision the route detectors cannot see, since a label is positioned independently of the line. Informational (no rating impact). |
| **Label on group** | `labelOnGroupCount` | A connection label rendered on a visual group's *title band* (top strip only) — the title collision the label-overlap detector skips, as it treats groups as transparent containers. A label in the group body is not flagged. Informational (no rating impact). |
| **Own icon over own label** | `ownIconOverLabelCount` | An element's own overlay icon drawn on top of its own title — a large specialization glyph burying the element name on a narrow box. Informational (no rating impact). The third icon axis, and structurally unreachable by the other two: `imageSiblingOverlapCount` compares an icon against sibling *boxes*, `overlayIconCollisionCount` against an *ancestor's* icon, and the icon rect is clamped to its own element box — so the icon and the title inside that same box are never compared. Tested against the title's **glyph run**, placed horizontally by the object's own `textAlignment` (LEFT on a `Grouping`, group or note — this server writes the same fixed type default Archi's palette does, so those three agree on any host; a plain element is left at CENTRE, which matches Archi on a stock installation but not on one where the user changed the `defaultArchiMateTextAlignment` preference Archi reads for it; and objects created through this server *before* that behaviour existed keep CENTRE regardless, so a model built across the change carries both), and placed vertically by the object's own `verticalTextAlignment` — TOP (Archi's default, so by far the common case), CENTRE or BOTTOM. The two axes are one mechanism, not two analogous ones: Archi's figure builds a single `GridData` and reads its horizontal alignment from `textAlignment` and its vertical from `verticalTextAlignment`, and this server publishes a parameter for each, so a centred or footed title is as reachable as a non-centred one. The band is anchored at whichever edge the title renders against — measured at the render, Archi insets it 4 px from that edge, which this detector rounds to the box edge itself (the same approximation the top-anchored model always made, kept so the change is the anchor alone). Its depth is the same wrap band `parentLabelObscured` uses — one 20 px label line, 40 when the name is too wide for the box and wraps, and never deeper than the object itself, because Archi clips a figure's contents to the figure; depth is chosen independently of the anchor, so a wrapped title grows from its own edge. Distinct from `labelOnGroupCount`, which tests the full-width title *band* — a different question, deliberately. An unmeasured label width yields no finding rather than a guessed rect; `fill` images are excluded. An icon-bearing named object whose title width **could not be measured** is not silently passed: it downgrades this dimension to `partial`, whether it is a visual Group (never measured) or an element whose text measurement failed. Both alignments are properties of the **view object**, not of the model element, so the remedy must be repeated on every view that shows the element. Informational governs the rating, not the prose: the count is named in `suggestions`, in `nextSteps` and in the whole-model sweep's per-view summary, while entering no rating. |
| **Overlay icon collision** | `overlayIconCollisionCount` | A container's corner overlay icon overlapping a *nested child's* own corner icon. Informational (no rating impact). Closes a structural blind spot in `imageSiblingOverlapCount`, which buckets objects by parent so an ancestor/descendant pair is unreachable, not merely unlisted. The containment chain is walked upward only, so each pair counts once; `fill` images are excluded on both sides. |
| **Note overlap** | `noteOverlapCount` | A note's box overlapping an element or a group. Informational (no rating impact) — notes are held apart from the scoring node set, so a view whose only defect is a note dropped on top of an element rates `excellent`. A note **nested inside** a container is not flagged: a note whose parent is the container it sits in is deliberate placement, not a collision. Counted per **(note, object) pair**, so one note lying across three elements reports 3 — the count can exceed the number of notes on the view. The dimension publishes no violator-id key, so past the 10-entry description cap the remaining pairs are recoverable only from the render. Remedy: move the note clear with `update-view-object`, or nest it inside the container it belongs to. |

### Related metric terms

- **HPQ** — Hub-port quality. The conversational name for the M5 `hubPortQualityScore`.
- **Hub-to-neighbour crowding / clearance floor** — The `hubNeighbourClearanceMin` signal and its 60 px crowding floor. Distinct from HPQ: HPQ scores how evenly a hub's ports are *distributed*; clearance measures whether the enlarged hub box leaves *room* for the neighbours it spreads onto. The two are orthogonal — a hub can score a perfect HPQ while crowding its neighbours.
- **V_p10** — Shorthand for the `parallelConnectionGap_V_p10` informational signal (the `vAxisParallelGapP10` field).
- **coincSeg / coincident segment** — A segment counted by the legacy `coincidentSegmentCount` metric: two *connections* running parallel and overlapping in the same corridor. Distinct from M4, which measures a connection coinciding with an *element edge*.
- **pass-through** — A connection whose route crosses *through* an element's body. A *self* pass-through (through its own source or target) is reported but does not affect the rating; a *cross-element* pass-through does.
- **coverage map / coverage declaration** — The `coverage` map `assess-layout` returns, declaring per defect dimension whether the run actually evaluated it: `checked` (detector ran and fully covers the dimension — absence means clean), `partial` (a detector ran but covers only *some* failure modes — render-verify the uncovered ones before certifying clean), `not-checked` (no detector — absence is unknown, not clean), or `not-applicable` (the view structurally cannot exhibit it). Informational; never affects a rating. A done-gate reads both `coverage` and `ratingBreakdown` — a dimension is clean only when `checked` *and* its breakdown passes. Most dimensions report a fixed registry level; the exceptions come in two kinds, **permanent** and **contextual** (both below), plus the standing `not-checked` on `corridorCentering`. The map is no longer something a consumer has to think to open: the assessor's own suggestion prose now reads it, scoping its verdict to the dimensions the run examined and stating how many it could not certify, and naming each contextual downgrade outright.
- **permanent `partial`** — A dimension declared `partial` on *every* run, because its detector's blind spot is unconditional and there is no run on which the uncovered mode is examined. Two dimensions ship this way. **`labelTruncations`**: `AssessmentCollector` measures label text only for non-group, non-note objects, so a visual group arrives with `labelTextWidth = 0` and `detectLabelTruncation` discards it at the first clause of its entry guard — and the same guard's non-positive-width arm discards an element whose measurement failed. A zero therefore certifies only that every *measured element* label fits; render-verify group titles. **`edgeCoincidence`**: `countConnectionEdgeCoincidence` classifies each segment as horizontal or vertical and skips everything else, so a diagonal segment is never compared against an element edge. Counts, descriptions and every rating are unaffected in both cases — only the coverage claim changed.
- **contextual `partial`** — A coverage value that depends on the run's findings rather than a fixed registry flag; the dimension is *declared* `checked` and downgraded only on a run that triggers it. Three dimensions do this. **`labelOverlaps`** downgrades when a label is wider than its hosting segment (`shortSegmentCount > 0`), because such a label can crowd a neighbour box while still clearing it geometrically — the overlap count is honestly zero, yet the crowding mode is unverified. **`ownIconOverLabel`** downgrades on a run holding a named icon-bearing object whose title width could not be measured — a visual group, which is never measured, or a `Grouping`/element whose text measurement failed — leaving its icon compared against nothing. **`parentLabelObscured`** downgrades on a run carrying a parent whose title band was never measured — a visual group, or an element whose `measureText` failed. Unlike the truncation detector, that parent *is* examined and does get a verdict, but `estimateLabelBandHeight` can never take its multi-line branch without a measured width, so the band is sized as a single 20 px line however long the title is (less, on a container shorter than that, since the band is clipped to the figure): Archi lays a group title out in a wrapping text flow over the whole group rectangle, so a long multi-word title can occupy a second row the band does not cover, and a child under that row goes unflagged on a dimension that vetoes the layout rating. Widening the band is not available — the wrapped height is unknowable without the measured width, and the wrap style is a user preference this code cannot read, so a computed band would be a guess wearing a measurement's clothing.
- **`corridorCentering` coverage** — A dimension shipped as a standing `not-checked`, making explicit that the R8 `corridorUtilisationScore` measures multi-occupant corridor *spread*, not whether a single route centres in its corridor band versus hugs an edge (a single-occupant corridor scores a vacuous 1.0; multi-occupant wall-hugging clamps to 1.0). `corridorUtilisation` itself stays `checked` — it fully covers its own scoped question.
- **`contextualPartialDimensions`** — A published list, on both the single-view `assess-layout` response and each entry of the `scope: "all-views"` sweep, naming the dimensions *this run* downgraded contextually. It is derived from the `coverage` map and the dimension registry, so it cannot disagree with the map beside it. Deliberately **not** every dimension reading `partial`: the two permanent `partial` declarations and the standing `not-checked` are present on every run by construction, so republishing them per view would bury the entries that are actually this run's news. The key is **always present** — an empty list is the positive, measured statement *nothing was left unexamined on this view*, not an abstention and not a dropped field, which is what lets a close-out sweep tell "nothing to render-verify" from "the sweep did not say". Informational; it enters no rating breakdown and moves no tier.
- **de-noised headline / `overallExcludingAcceptedCosmetics`** — A key in `ratingBreakdown`: the overall rating recomputed with the `nonOrthogonalTerminals` (diagonal ELK terminal-segment) contribution removed. A *floor, never a lift* — it can only equal or improve `overallRating`. When it is better than `overallRating`, the headline `fair` is accepted terminal cosmetics only (clear with `auto-route-connections` mode `terminals-only`, or accept); when the two are equal, the rating reflects a real defect.

## Rating tiers

The overall rating uses a severity-tiered model so cosmetic issues cannot mask structural ones. Each metric belongs to a tier, and each tier caps how far it can pull the rating down.

| Tier | Severity | Effect on rating |
|---|---|---|
| **Tier 1** | Critical | Drives the overall rating directly (no cap). |
| **Tier 2** | Moderate | Capped at `fair`. |
| **Tier 3** | Cosmetic | Capped at `good`. |

Tier 1 is split by what the defect affects:

- **Tier 1L** — A critical *layout* defect (for example, sibling overlap, or a parent's label obscured by a child). Caps the **layout tier** at `poor`.
- **Tier 1R** — A critical *routing* defect (pass-throughs, M2 interior terminations, M3 zigzags, connection-vs-connection coincident segments). Caps the **routing tier** at `poor`. M4 (`connectionEdgeCoincidence`) is Tier 2R and enters this band only when its count is egregious.

Rating levels run `excellent` → `good` → `fair` → `poor`. The **M6** overall rating reports the layout tier and routing tier separately and takes the worse of the two, so a routing fix on a well-laid-out view does not drag its layout tier down (and vice versa).

## Routing and layout terms

- **Hub element** — An element with many connections (5 or more is the detection threshold). Hubs need enough perimeter length to spread their connection ports; `detect-hub-elements` suggests a size.
- **Perimeter / perimeter-terminal** — The boundary face of an element where a connection attaches. A perimeter-terminal is a connection endpoint locked to a face slot on that boundary.
- **Corridor** — The axis-aligned channel of free space between elements (or between groups) through which connections are routed. Wider corridors carry more parallel routes without crowding.
- **Clearance** — The perpendicular distance between a routed segment and the nearest obstacle. The router weights paths to keep clearance high, so lines do not hug element edges.
- **Channel nudging** — A post-routing pass that shifts parallel segments sharing a channel so they spread out evenly instead of overlapping.
- **Bendpoint** — A corner point on an orthogonal route where the connection changes axis.
- **Zigzag** — A route that backtracks or reverses direction along an axis; counted by M3 (`zigzagCount`).
- **Visibility graph** — The graph of obstacle-free straight-line connections the router searches over.
- **A\* pathfinding** — The shortest-path search the router runs over the visibility graph, weighted by clearance and corridor preferences.
- **ELK (Eclipse Layout Kernel)** — The external layout library used for automatic hierarchical (`Layered`) placement of elements.
- **Precondition** — A property of the view's geometry (hub sizing, inter-element spacing, inter-group arrangement) that must hold *before* routing. The pipeline can refine routes but cannot create these conditions; see the `archimate://prompts/routing-preconditions-checklist` resource.
- **Density floor / reflow** — The point at which a view has too many elements for its area and no amount of spacing can satisfy a precondition. The spacing tools detect this and offer a structural *reflow* (repositioning elements) rather than churning.

## Tool behaviour terms

- **Control loop** — The internal `observe → decide → terminate` cycle the spacing convenience tools run: take a small spacing step, re-run `assess-layout`, then continue, escalate, or stop. One tool call is one undo-stack entry regardless of how many iterations run.
- **Density-aware termination** — The control loop's stop logic. It stops when quality is reached, when more spacing provably cannot help (density floor), or when the iteration budget is exhausted; a step that degrades the loop's own six-input step scalar is reverted — but that scalar is narrower than `overallRating`, so a completed run can still leave the view rated worse than it found it, which the three spacing tools report as a `SPACING_RATING_REGRESSED` structured warning.
- **`terminationReason`** — The field a spacing tool returns explaining *why* its control loop stopped (for example, target reached, budget exhausted, or a structural reflow is required).
- **Infeasibility certificate** — A sound, pre-loop check that proves a view's spacing precondition cannot be satisfied on its current canvas. When it fires, the tool returns the view untouched and offers a structural reflow.
- **autoNudge** — An `auto-route-connections` mode that automatically moves a blocking element (and resizes its parent group to contain it), then re-routes, in one atomic operation.
- **Effective state** — What the model holds *after* a write, as opposed to what the caller requested. Every mutating tool's success response must report effective state: Archi auto-fits a container to its children, so a requested rectangle may not survive, and the client is an agent that cannot see the canvas. A response that echoes the request while the model diverged is a correctness defect, not a cosmetic one. See [Mutation Model — Effective-State Reporting](mutation-model.md#effective-state-reporting).
- **Container (on a view)** — Either of the two Archi objects that render as a labelled box holding other objects: a **native view group** (`IDiagramModelGroup`, from `add-group-to-view`) or an ArchiMate **`Grouping`** element placed on the view. The arrangement family treats them alike; the wider layout family does **not**, and the differences are deliberate in every case but one. Seven predicates decide the question, each for a different reason; the per-tool table is in [Layout Engine — What counts as a container](layout-engine.md#what-counts-as-a-container). **Top-level means the outermost qualifying container, wherever it sits** — a zone drawn inside a host the predicate declines is top-level, and every route agrees. Seeing it is family-wide; positioning it is `arrange-groups` only, in the host's own coordinate space. Do not infer one tool's answer from another's.
- **Upward propagation** — `layout-within-group`'s `recursive` option: after fitting the container you named, walk *up* the parent chain re-fitting each enclosing container to its now-larger child. It is scoped to **native view groups at both ends** — it starts only from one and stops at the first ancestor that is not one — so an ArchiMate `Grouping` or element acting as a container is neither a valid starting point nor walked past. Distinct from `recursiveChildren`, which propagates *arrangement* downward — and which is scoped *wider*, not narrower, admitting any element that holds children. The two directions are deliberately different questions; see **Container (on a view)**. See [Layout Engine](layout-engine.md#layout-within-group).
- **`ancestorPropagation`** — The field reporting how that upward pass ended, as a stable code plus a short phrase, on **every** `layout-within-group` response. Eight values, from `not-requested` through `container-not-a-native-group` and `stopped-at-non-native-ancestor` to `propagated`. Present even when nothing was asked for, because the count does not identify the reason in either direction: only `propagated` guarantees a count above zero, five codes always report zero, and `stopped-at-non-native-ancestor` and `depth-cap-reached` each arrive with either — so a zero-only explanation would have been silent on the two cases that leave work undone. Codes are published: once shipped a code is never renamed, only superseded.
- **Collateral report** — The fields naming what a call changed that the caller never named: `resizedAncestors` and `resizedGroups` (containers the call grew, with the rectangles they ended at) and `movedObjects` (objects anchored to something the call moved or grew, with where they landed). A count or a flag does not discharge the obligation — reporting *that* something changed without *what it changed to* leaves the agent unable to act.
- **Gap registry** — `tools/effective-state-gaps.txt` plus `EffectiveStateContractTest`. Every registered tool must classify exactly once as read-only, oracle-covered, or a declared gap with a stated reason; a tool classified nowhere fails the build. The entry count is a lower-only ceiling, clicked down in the same commit that closes a gap.
- **Disclosure contract** — The approval-card counterpart of the effective-state rule. A proposal's `proposedChanges` map is the only description of a pending write anyone gets (verbatim onto the wire via `list-pending-approvals`, verbatim into the card's `Technical details`, and the source the card's rows and headline sentence are derived from), so every parameter the approval will apply must be in it and a parameter the write never applies must not — under-disclosing hides a write, over-disclosing invents one. The card's prose is keyed on the map's own **keys**, not on parameter names, so description and validation cannot describe a call two ways. Held by `ApprovalCardContractTest` plus `tools/approval-card-gaps.txt`: every proposal site classifies exactly once as complete or exempt-with-reason, a site classified nowhere fails the build, and the entry count is a lower-only ceiling. See [Mutation Model — The disclosure contract](mutation-model.md#the-disclosure-contract).
- **Preview labelling** — How batch and approval modes discharge the effective-state rule. Nothing is effective in those modes by construction, so the entity is nested under `preview` beside a `batch` or `proposal` sibling and never appears at the top level of `result`. Not to be "fixed" by resolving at prepare time — that re-creates the divergence the label declares.
- **Execute-time guard** — An integrity precondition re-checked inside `execute()` rather than at prepare. Prepare-time-only guards are worthless on deferred paths, where a sibling operation queued in the same batch can invalidate them before the command runs. An execute-time guard is path-agnostic (one implementation covers batch, bulk and approval) and *declines* the single operation with a named skip reason instead of proceeding.
- **`scope: all-views`** — An `assess-layout` mode (vs the default `single`) that assesses every diagram in the model and returns a compact per-view summary map (`name`, `overallRating`, `overallExcludingAcceptedCosmetics`, and the key counts) instead of one full payload per view — a one-call close-out triage, after which the agent drills into any `fair`/`poor` view with a single-scope call.

## Reference baseline

- **Manual-routed reference (oracle)** — A hand-routed ArchiMate view used to calibrate metric thresholds and to pin them with regression tests. Metric anchor values quoted in the documentation (for example, the `parallelConnectionGap_V_p10` anchor of 13.30 px) are measured against this reference.
